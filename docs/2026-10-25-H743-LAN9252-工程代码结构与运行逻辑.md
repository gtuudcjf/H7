# H743–LAN9252 工程代码结构与运行逻辑

记录日期：2026-10-25

工程目录：`D:\STM32MX\H743-VOFA`

分析基准：最近联调使用的 `motor_build_openanglebenchcheck.uvprojx` 及当前工作区源代码。

本文整理 EtherCAT SPI 通信与电机联调的关键代码、模块职责及完整运行链路，便于后续维护和阶段汇报。本次仅整理文档，没有修改固件、下载程序或进行新增实机测试。

> 当前已实现的链路是：TwinCAT 下发指令 → LAN9252 交换 PDO → STM32 校验并执行命令 → 虚拟电角度＋电流 PI → PWM 驱动电机。最近在正向给定 6、12 时旋转的电机，使用的是该路径，不是编码器速度闭环。

最近联调使用的 Keil 工程：

| 编译宏 | 当前值 | 含义 |
|---|---:|---|
| `ETHERCAT_BRINGUP_ONLY` | 0 | 不再仅验证 EtherCAT 通信 |
| `ETHERCAT_MOTOR_CONTROL` | 1 | 启用 EtherCAT 电机指令处理 |
| `ETHERCAT_MOTOR_OPEN_ANGLE` | 1 | 采用虚拟电角度、电流闭环 |
| `ETHERCAT_MOTOR_POWER_ENABLED` | 1 | 软件允许申请功率输出，但仍须满足运行许可 |

## 二、完整控制链路

```text
TwinCAT：MAIN 中操作 bStart、bStop、rDemandRpm
                    │
                    ▼
PLC 状态机生成 ControlWord、TargetSpeed、CommandSequence
                    │
              EtherCAT 网线
                    ▼
                 LAN9252
                    │
           SPI1：读命令、写反馈
                    ▼
        SSC 协议栈与 PDO 映射
                    │
                    ▼
       电机命令校验状态机 EMC_Core
                    │
                    ▼
       EtherCATMotorBridge 桥接执行
                    │
                    ▼
        MotorControl 电机控制编排
                    │
      虚拟电角度＋ADC反馈＋电流PI
                    │
                    ▼
             SVPWM → TIM8
                    │
              六路 PWM 信号
                    ▼
         DRV8323 → 三相功率桥 → 电机
```

反馈沿相反方向返回 TwinCAT。

### 三类接口必须区分

| 接口 | 用途 |
|---|---|
| SPI1 | STM32 与 LAN9252 通信，读写寄存器和过程 RAM |
| SPI2 | 配置及读取 DRV8323 寄存器 |
| TIM8 PWM | 实际控制功率桥开关，驱动电机 |

SPI2 本身不传输三相 PWM 波形。当前 OpenAngle 分支也不依赖编码器 SPI4 提供转子位置。

## 三、上电后的初始化与调度

关键入口：[main.c](../Core/Src/main.c)。

- `motor_config`：约第 103 行，选择当前分支的控制算法。
- `main()`：约第 140 行，完成初始化与主循环。
- `HAL_TIM_PeriodElapsedCallback()`：约第 384 行，分派 TIM6 和 TIM8 中断任务。
- `HAL_ADCEx_InjectedConvCpltCallback()`：约第 403 行，读取两路注入转换值。

### 3.1 当前网络电机分支的启动顺序

1. 配置 MPU、HAL 和系统时钟。
2. 初始化 GPIO，软件首先要求驱动禁能、LAN9252 片选空闲。
3. 初始化 SPI1、ADC1、SPI2、TIM6、TIM8。
4. 调用 `MotorSafety_Init()`，初始化独立指令保护。
5. 调用 `MotorControl_Init()`，初始化电机控制对象，并预置零速度命令。
6. 启动 TIM6 的保护中断。
7. 调用 `EtherCATMotorBridge_Init()`，初始化命令桥接层。
8. 调用 `EtherCAT_Init()`，初始化 LAN9252 和 EtherCAT 协议栈。
9. 进入主循环。

当前网络控制分支不会像旧本地运行分支一样，上电直接调用 `MotorControl_Start()`。只有收到满足条件的网络启动命令后才启动电机。

### 3.2 主循环

```c
while (1)
{
    EtherCAT_Service();
    EtherCATMotorBridge_Service();
}
```

- `EtherCAT_Service()`：处理协议栈、过程数据和通信诊断。
- `EtherCATMotorBridge_Service()`：执行启动、停止、清故障和更新运行目标。
- 实时电流控制不放在该循环中，避免主循环中的 SPI 访问耗时直接决定控制周期。

`ethercat_motor_app.inc` 由 [ethercat_app.c](../Core/Src/ethercat/ethercat_app.c) 在电机构建分支中包含，并非遗漏编译的独立源文件。

### 4.1 SPI1 当前配置

`MX_SPI1_Init()` 位于 `spi.c` 约第 35 行；引脚配置位于约第 205 行。

| 项目 | 配置 |
|---|---|
| SCK / MISO / MOSI | PA5 / PA6 / PA7 |
| 软件片选 | PA4 |
| 数据格式 | 8 位、MSB 优先 |
| 时钟模式 | 空闲低、第一边沿采样，即 Mode 0 |
| 分频 | `/16` |
| 收发方式 | 阻塞式 `HAL_SPI_TransmitReceive()`，非 DMA |

板级 `board_transfer()` 位于 `lan9252_board.c` 约第 81 行。它负责有时间预算的 HAL 收发；片选由更上层的完整事务统一控制。HAL 故障保留在 `g_lan9252_hal_fault`。

### 4.2 LAN9252 的三类访问

| 类型 | 主要函数 | 用途 |
|---|---|---|
| 直接访问 | `direct()`，约第 72 行 | 访问 `BYTE_TEST`、`HW_CFG`、`ID_REV` 等系统寄存器 |
| CSR 间接访问 | `csr()`，约第 147 行 | 访问 AL 状态、AL 事件、SyncManager 等 ESC 控制寄存器 |
| PRAM FIFO 访问 | `pram()`，约第 178 行 | 读写 EtherCAT 过程 RAM，承载 PDO 和邮箱等数据 |

上述位置均位于 `lan9252_spi.c`。`esc()` 按访问地址选择 CSR 或 PRAM 路径。SPI 快读命令为 `0x0B`，写命令为 `0x02`。

因此，STM32 并不是直接将 C 变量通过 SPI 发送给 TwinCAT，而是读写 LAN9252 的寄存器和过程 RAM，再由 LAN9252 与主站交换数据。

### 4.3 初始化探测

`LAN9252_Probe()` 检查：

- `BYTE_TEST == 0x87654321`。
- 硬件 Ready。
- 芯片 ID。
- SPI PDI 配置。
- EEPROM 状态。

探测通过只是底层具备工作条件，不等于从站已经进入 OP。

### 4.4 SSC 采用主循环轮询

配置位置：[ecat_def.h](../Middlewares/Third_Party/EtherCAT_SSC/Inc/ecat_def.h)，约第 167 行起。当前关闭 ESC 中断和 DC 支持。

```text
EtherCAT_Service()
 → SSC MainLoop()
 → 查询 AL Event
 → 有新输出事件时读取 RxPDO
 → 处理应用和协议状态机
 → 更新 TxPDO
```

`MainInit()` 位于 `ecatappl.c` 约第 494 行，`MainLoop()` 位于约第 532 行。栈内 1 ms 时间处理由主循环消费计时差值，单次限制追赶次数。

当前系统不是 DC 同步触发的 EtherCAT 伺服控制。通信访问失败会保留故障并停止正常服务，不是无限自动重试、自动清错。

## 五、TwinCAT 命令如何进入 MCU

### 5.1 PLC 状态机

关键文件：[MAIN.TcPOU](../EtherCAT/motor/openangle/plc/MAIN.TcPOU)。控制字和目标由 PLC 程序生成，不应直接强制映射的 PDO 输出。

| `nPhase` | 含义 | 行为 |
|---:|---|---|
| 0 | 待机 | 等待通信健康、Ready 和新的启动边沿 |
| 10 | 启动等待 | 发送使能，速度保持零，等待启动和对齐完成 |
| 20 | 运行 | 将 `rDemandRpm × 10` 写为 `TargetSpeed` |
| 30 | 停止过程 | 保持使能、发送零速度，由 MCU 按斜坡退出 |
| 80 | 复位等待 | 等待 MCU 故障清除及电气输出关闭 |
| 90 | 故障锁存 | 撤销运行命令，等待显式复位 |

`startEdge`、`resetEdge` 使用上升沿检测。发生故障后，即使通信恢复到 OP，`nPhase` 也可能继续保持 90；复位要求 `bStart=FALSE`，再产生新的 `bReset` 上升沿。

PLC 每个周期推进 `CommandSequence`，除非启用 `bFreezeHeartbeat`。通信健康判据为 `State=8` 且 `WcState=FALSE`，但它不代表电机已启动。

### 5.2 PDO 字段与单位

变量声明：[GVL_MotorIO.TcGVL](../EtherCAT/motor/openangle/plc/GVL_MotorIO.TcGVL)。

| 方向（从站视角） | 长度 | 字段 |
|---|---:|---|
| RxPDO：主站 → STM32 | 8 字节 | `ControlWord`、`TargetSpeed`、`CommandSequence` |
| TxPDO：STM32 → 主站 | 20 字节 | `StatusWord`、`CycleCounter`、`ActualSpeed`、`ActualIq`、`MotorFault`、`BridgeFault`、`ActiveTargetSpeed`、`AcceptedSequence` |

`TargetSpeed` 和 `ActiveTargetSpeed` 的单位为等效磁场速度 `0.1 rpm`；`ActualIq` 的单位为 mA。

| 控制字 | 当前配置中的含义 |
|---|---|
| `0x0100` | 确认虚拟角度控制配置，不使能运行 |
| `0x0101` | 确认配置并请求运行 |
| `0x0180` | 确认配置并请求故障复位 |

这是自定义的控制协议，不是标准 CiA402 控制字状态机。

`APPL_OutputMapping()` 位于 `ethercat_motor_app.inc` 约第 80 行，接收并交付命令；`APPL_InputMapping()` 位于约第 89 行，返回反馈。字段按线上字节布局打包，不能直接将带对齐填充的对象字典结构体 `memcpy` 到 PDO。

### 5.3 MCU 命令校验状态机

关键文件：[ethercat_motor_core.c](../Core/Src/ethercat/ethercat_motor_core.c)，主要入口 `EMC_Receive()` 位于约第 49 行。

检查内容包括：链路有效性、报文长度、控制字、速度范围、配置确认位、命令序号、100 ms 新鲜度、启动条件及电机反馈。

```text
DISARMED → READY → STARTING → RUNNING
     ↑                           │
     └──── 停止或发生故障 ────────┘
```

- 进入 Ready 前，需要连续收到符合要求的三个新序号零命令，并满足启动许可。
- 启动沿对应的线上速度必须为零。
- 重复序号不能续期指令心跳；禁止命令仍具有相应停机作用。
- 故障会撤销运行目标、请求停止并锁存，不自动重新启动。

所以，可以在 TwinCAT 中提前预置 `rDemandRpm=6`，但 PLC 在阶段 10 仍先发送零速度，进入阶段 20 后才发送 `TargetSpeed=60`。

### 5.4 桥接层执行动作

关键文件：[ethercat_motor_bridge.c](../Core/Src/ethercat/ethercat_motor_bridge.c)。

- `EtherCATMotorBridge_Receive()`：约第 76 行，接收 PDO、处理心跳与即时撤销条件。
- `EtherCATMotorBridge_Service()`：约第 98 行，前台执行动作。
- `Observe()`：约第 21 行，收集电机反馈并转换为线上单位。

```text
START → MotorSafety_Arm() → MotorControl_Start()
STOP  → 撤销输出资格 → MotorControl_Stop()
CLEAR → 停止/清电机故障 → 清保护锁存
运行目标 → MotorControl_SetOpenAngleSpeedCommand()
```

## 六、电机启动与运行逻辑

关键编排文件：[motor_control.c](../Core/Src/motor/motor_control.c)。它组织状态和调用顺序，不重复实现底层 PI、坐标变换和 SVPWM。

### 6.1 启动顺序

`MotorControl_Start()` 位于约第 1763 行，依次执行：

1. 检查指令及输出许可，确认当前允许启动。
2. ADC 自校准。
3. 唤醒并配置 DRV8323。
4. 电流零偏校准：丢弃 16 组样本，平均 256 组。
5. 退出 CSA 校准，获得两相电流零偏。
6. 保持三相 PWM 关闭，执行约 100 ms 的基线诊断。
7. 使能三相 PWM，固定角度对齐：目标 `Id=0.5 A、Iq=0`，对齐阶段约 0.75 s。
8. 进入运行：目标 `Id=0、Iq=0.8 A`，按命令推进虚拟电角度。

电流参考带斜坡，不是瞬间阶跃。当前 100 ms 基线是联调过程中保留的诊断环节，不是用户必须手动执行的一项额外测试。

### 6.2 本轮运行策略

关键文件：[open_angle_experiment.c](../Core/Src/motor/open_angle_experiment.c)。

`OAE_Step()` 负责对齐、等待非零速度、运动、减频、撤电流、停止，以及时限和禁止运行中直接换向等规则。

速度换算：

```text
电角频率 Hz = 等效速度 rpm × 极对数 / 60
```

当前极对数为 10：给定 6 对应 1 Hz 电角频率，给定 12 对应 2 Hz。

这是旋转磁场的等效速度，不是测得的转子机械速度。当前方向由虚拟电角频率的正负决定，并不是简单将运行 `Iq` 改为负数。实际反向转动仍须与已完成的正向实机结果分开记录。

### 6.3 电机内部两类状态

- `MotorControlMode`：回答“采用哪种控制算法”。当前运行算法为 `MOTOR_CONTROL_OPEN_ANGLE_CURRENT`。
- `MotorRunState`：回答“启动流程走到哪一步”，如电流校准、Ready、对齐、运行、故障。

枚举定义：[motor_runtime_policy.h](../Core/Inc/motor/motor_runtime_policy.h)。

## 七、实时控制与中断分工

| 执行位置 | 周期/触发 | 任务 |
|---|---|---|
| 主循环 | 尽快轮询 | EtherCAT 和启动、停止等前台动作 |
| TIM6 中断 | 1 ms | 指令心跳、会话和运动时限检查 |
| TIM8 更新中断 | 约 100 μs | 推进虚拟电角度、检查采样新鲜度 |
| ADC 注入序列完成中断 | PWM 同步触发，约 10 kHz | 两相电流处理、保护、电流 PI、写 PWM |

`motor_control.c` 中的核心函数：

- `MotorControl_FastTick()`：约第 2010 行，当前路径主要准备角度。
- `MotorControl_CurrentSampleComplete()`：约第 2139 行，用新鲜样本计算电流环输出。
- `MotorControl_RunCurrentLoop()`：约第 986 行，选择参考、执行斜坡和 PI。
- `MotorControl_WriteVoltage()`：约第 372 行，统一进入 SVPWM 和 PWM 写入。

### 7.1 ADC 与 PWM 同步

配置入口：

- [adc.c](../Core/Src/adc.c)：注入通道配置约第 109 行。
- [tim.c](../Core/Src/tim.c)：TIM8 配置约第 72 行。

```text
TIM8 CH4 / OC4REF → TRGO2 → ADC1 注入转换
PB1 / I_A → Rank1
PB0 / I_B → Rank2
两通道序列完成 → 回调读取 JDR1/JDR2
```

CH4 用于内部采样触发，不输出到电机相线。当前采用序列完成中断，避免第一通道刚完成就读取两通道结果。Bench 配置下 ADC 分频为 DIV2；该调整不能被表述为电流采样异常根因已经解决。

### 7.2 电流闭环计算链

```text
ADC 原始值
 → 扣零偏、换算 Ia/Ib
 → Ic = -(Ia + Ib)
 → Clarke 变换
 → 使用虚拟电角度做 Park 变换
 → Id/Iq 反馈与目标比较
 → 电流 PI 计算 Ud/Uq
 → SVPWM 计算三相占空比
 → 写 TIM8 CCR1/2/3
```

| 文件 | 主要职责及入口 |
|---|---|
| [current_sense.c](../Core/Src/motor/current_sense.c) | `CurrentSense_Convert()`，约第 134 行；物理量换算、第三相重构 |
| [foc_transform.c](../Core/Src/motor/foc_transform.c) | `Foc_Clarke()`、`Foc_Park()` |
| [current_pi.c](../Core/Src/motor/current_pi.c) | `CurrentPi_StepDq()`，约第 135 行；电流 PI、限幅、抗饱和 |
| [open_loop.c](../Core/Src/motor/open_loop.c) | `OpenLoop_Step()`，约第 56 行；频率斜坡与角度积分 |
| [svpwm.c](../Core/Src/motor/svpwm.c) | `Svpwm_Compute()`，约第 41 行；电压矢量转三相占空比 |
| [pwm_3ph.c](../Core/Src/motor/pwm_3ph.c) | `Pwm3ph_ApplyDuty()`、`Pwm3ph_Enable/Disable()`；TIM8 输出封装 |

### 7.3 DRV8323 配置

- [drv8323_board.c](../Core/Src/motor/drv8323_board.c)：板级 SPI、片选、使能、CAL 绑定和启动寄存器诊断。
- [drv8323.c](../Core/Src/motor/drv8323.c)：约第 128 行 `Drv8323_EnableAndConfigure6Pwm()`，处理唤醒、6PWM、CSA、OCP 配置。

TIM8 生成三相主/互补 PWM；DRV8323 将输入逻辑转换为 MOSFET 栅极驱动。不可将“SPI 配置成功”等同于三相 PWM 已经输出。

## 八、保护、反馈与参数入口

### 8.1 多层保护

- [motor_safety.c](../Core/Src/motor/motor_safety.c)：`GateOff()` 撤销驱动使能并清 TIM8 `MOE`；提供申请、撤销和复位输出许可的接口。
- [motor_command_guard.c](../Core/Src/motor/motor_command_guard.c)：指令心跳及独立运行时限策略。
- `ethercat_motor_core.c`：网络命令、序号、通信状态和启动超时检查。
- `open_angle_experiment.c`：本轮运动、换向、减速与会话策略。
- `motor_control.c`：ADC 范围、采样超时、计算有效性和过流检查。

TIM6 的保护不依赖主循环正常完成一次通信服务，但它仍是 MCU 软件中断保护，不等于独立硬件安全系统，也不能保证 MCU 被调试器暂停时继续执行。

当前主过流关断路径为：计算的相电流超过 10 A，连续两次触发。`0.6 A` 现在仅为诊断统计阈值，不是该路径的关断阈值。另有 OAE 三样本检查；相同阈值下，原有两次确认路径会先触发。

恢复旧过流阈值是阶段取舍，不表示采样异常已经修复，也不构成硬件安全证明。

### 8.3 四种状态不能混淆

| 状态 | 来源 | 回答的问题 |
|---|---|---|
| `State=8` | EtherCAT 从站状态 | 通信是否处于 OP |
| `nPhase` | TwinCAT PLC | 上位控制流程走到哪一步 |
| `EMC_Core.state` | MCU 命令层 | 网络命令是否就绪、启动或运行 |

### 8.4 反馈值与调试变量的含义

| 变量 | 正确理解 |
|---|---|
| `ActualSpeed` | 当前路径没有有效转子速度测量；零值不能证明实际停转 |
| `ActualIq` | 虚拟坐标系下计算的 q 轴电流，不能直接等同真实转矩电流 |
| `AcceptedSequence` | MCU 接受的命令序号，不是动作完成标志 |
| `CycleCounter` | 满足运行条件时随桥接轮询递增，不是精确的 EtherCAT 帧计数或转子计数 |
| `MotorFault` | 电机控制层故障，例如 7 为软件过流 |
| `BridgeFault` | 网络命令、配置及运行策略故障，例如 12 为运行时限相关故障 |
| `g_motor_control_debug` | 当前模式、阶段、ADC 原始值、零偏、Id/Iq 和参考值等 |
| `g_motor_openangle_diagnostics` | 本次启动及运行的 RAM 历史诊断 |
| `g_motor_openangle_baseline_diagnostics` | 三相 PWM 关闭基线诊断 |
| `g_drv8323_startup_diagnostics` | 驱动配置结果与寄存器读回诊断 |
| `g_lan9252_first_fault` / `g_lan9252_hal_fault` | 首次 SPI 协议/底层 HAL 访问故障证据 |

RAM 诊断仅用于观察；稳定的会话快照应在 `active=0` 后读取。断电会丢失这些历史记录，不应直接修改诊断字段来控制电机。

## 十、建议阅读顺序与阶段结论

### 建议阅读顺序

1. `main.c`：启动、主循环、中断分工。
2. `MAIN.TcPOU`：操作变量如何生成命令。
3. `ethercat_motor_app.inc`：线上字段如何进入 MCU。
4. `ethercat_motor_core.c`：命令校验和状态转换。
5. `ethercat_motor_bridge.c`：网络动作如何调用电机接口。
6. `motor_control.c`：启动、采样、运行、停止及故障处理。
7. `open_angle_experiment.c`：本轮运行规则。
8. `current_sense.c`、`foc_transform.c`、`current_pi.c`、`open_loop.c`、`svpwm.c`、`pwm_3ph.c`：控制算法与输出。
9. `lan9252_spi.c`、`lan9252_board.c`、`lan9252_port.c`：追溯底层通信细节。

### 阶段结论

已建立 TwinCAT—LAN9252—STM32 的 EtherCAT 指令和反馈链路，将网络通信与实时电流控制分层，通过命令校验、启动对齐、虚拟电角度、电流 PI 和 PWM 输出，实现电机在正向 6、12 等效速度给定下旋转。

当前证据不等同于完成以下事项：

- 实际转速准确性或编码器速度闭环验证。
- 反向实机转动验证。
- 电流采样异常根因修复及保护有效性完整核查。
- 平滑度和电流噪声改善验证。
- 最新延长时限配置的新增实机验证。

本记录中的代码行号为 2026-10-25 分析快照，后续修改可能导致行号移动，应优先按文件名和函数名定位。
