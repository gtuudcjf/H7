# H743 LAN9252 HBI OP implementation

Approved specification: user-approved plan in this chat, 2026-10-24.

Goal: reuse SPI OP commit 60f64449 SSC/app/service with FMC16 single-phase HBI,
PDI 0x89, default communication-only firmware, motor disabled.

Tasks:
- [x] Import the selected SSC/application and reusable regression tests, preserving motor sources.
- [x] Test then implement paired-halfword HBI transport, bounded CSR/PRAM and probe.
- [x] Test then implement FMC/MPU and GPIO startup isolation; update Keil and CubeMX.
- [x] Supply HBI revision 2 ESI and a complete commissioning runbook.
- [x] Run host regressions, both ARMCC builds, inspect map/disassembly and record firmware hashes.
- [x] Review the complete change and fix actionable findings.

Constraints: Bank4 0x6c000000; FMC240 MHz 15/15/63/15 mode A, no wait/burst/write FIFO;
64KB Device XN MPU override; two ordered volatile halfword accesses per DWORD;
>=1us inter-DWORD guard; Direct1ms/CSR10ms/PRAM10ms/probe100ms budgets.
PB5 and PC4 low; PA4..7 and PF0 high impedance; PF1 ALEHI high; no motor peripherals
or motor callbacks in bringup mode. CoE FreeRun polling, 2-byte Rx/6-byte Tx, no DC.
ESI vendor0x00f0c743 product0x9252 revision2 serial1, config890E80CC8813F000000000800000.
Hardware writes and OP acceptance are operator steps, not software-test claims.

## Execution ledger

- Setup: reuse the user-selected EtherCAT-HBI checkout; no branch/worktree relocation.
  Initial tracked tree is clean; reference PDFs and F407 example are user-owned untracked files.
- Pre-flight: driver -> port -> SSC/service APIs retain logical names and byte-buffer semantics;
  physical SPI transport is replaced with read16/write16/finish_dword/time callbacks.
  ESI/firmware identities change together. Motor implementation sources remain unchanged.
- Baseline: original motor suite could not run with the missing TinyCC archive.
  Found installed GCC 16.2 and added shared compiler discovery; all eight existing
  motor checks passed. No dependency installation or motor-source edits.
- Driver: new halfword bus test first failed because the implementation was
  absent. Final tests cover 1..130-byte PRAM reads/writes at all four offsets,
  FIFO starvation, CSR alignment, invalid requests, timeouts and wrap.
- Ruling: MPU TEX/C/B=010/0/0 is non-shareable Device, used to satisfy the
  approved non-cacheable/non-bufferable peripheral window. Region1 overrides
  region0; actual MPU function is exercised by host tests.
- Ruling: CubeMX NOR describes the bus, but LAN9252 must not receive NOR flash
  discovery commands. Preserve custom HAL_SRAM configuration in USER CODE 0
  and early return in FMC_Init 0. Full regeneration was not performed.
- Tests: independently mutated halfword offsets, removed DWORD recovery guard,
  and drove PB5 high in scratch copies. The respective tests rejected all three.
- Review: fresh whole-change review found the missing Cortex-M7 DWT unlock.
  A locked-start test failed before the fix. Added LAR unlock and a bounded
  progress self-check; failure records ERR_CLOCK=12 before any HBI access.
  Board locked/stalled-counter and port no-probe regression tests now pass.
  Reviewer rechecked the fix and reported no new defect.
- Final ESI check found object 0x1008 still declared the SPI 16-byte name.
  Added a failing device-name length/default-data regression; corrected it to
  STRING(20), 160 bits and the HBI name bytes. Firmware already serves that name.
- Final software validation: HBI suite passes (481501 driver checks; locked and
  stopped DWT; GPIO/FMC/MPU; port/service; real SSC/SDO/mailbox/PDO). Existing
  eight-entry motor suite passes. ARMCC 5.06u5 full rebuild for mode0 and mode1:
  both 0 errors/0 warnings. Actual ARM preprocessing confirms isolation, and
  map/disassembly confirms HBI/SSC plus LDRH/STRH/DSB with no linked motor start.
  Final communication HEX SHA256: B625E92559F5C61BA1B5AA392070EB4E400376D177E240E60F57AF0769BC4E6C.
- Hardware: no flashing, EEPROM write, TwinCAT configuration, or OP acceptance
  was performed. Operator acceptance remains explicitly separate from software.
