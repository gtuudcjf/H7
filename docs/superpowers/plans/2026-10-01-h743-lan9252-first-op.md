# H743 LAN9252 First OP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有 STM32H743 电机控制工程中增加隔离的 LAN9252 EtherCAT 从站链路，使实验设备能按 `INIT -> PREOP -> SAFEOP -> OP` 运行，并通过 2 字节 RxPDO 与 6 字节 TxPDO 完成可观测的轮询回环，同时始终禁止电机功率级启动。

**Architecture:** 采用五层边界：纯 C 的 LAN9252 SPI/CSR/PRAM 协议核心、STM32H743 HAL 传输适配、SSC 5.11 硬件接口、最小 CoE/PDO 应用、主循环服务与诊断。ESI、SII、SSC 身份和对象字典使用同一组常量并由静态测试交叉校验；首版采用 FreeRun 轮询，不启用 DC、SYNC/IRQ、DMA 或电机命令。

**Tech Stack:** STM32CubeMX/STM32H7 HAL、Keil MDK-ARM、LAN9252 SPI PDI、Beckhoff EtherCAT SSC 5.11（取自仓库内 F407 参考资料）、TwinCAT 3、PowerShell、TinyCC 主机单元测试。

**Spec:** `docs/superpowers/specs/2026-10-01-h743-lan9252-first-op-design.md`

## Global Constraints

- 保留现有 SPI2（DRV8323）、SPI3/SPI4（编码器）、电机算法、参数和 VOFA 观测逻辑；本计划不得借机重构这些模块。
- 首次 OP 固件固定定义 `ETHERCAT_BRINGUP_ONLY=1`。该定义有效时，不调用 `MotorControl_Start()`，不启动 TIM8 PWM、ADC 电流闭环、电机校准或任何运动命令。
- PA4 为 LAN9252 CS，PA5/PA6/PA7 为 SPI1 AF5，PE0/PE1/PE3 只作为无中断输入；PE2 继续属于 SPI4。
- SPI1 初始速率为 4 MHz：64 MHz SPI123 内核时钟、Prescaler 16、Mode 0、8 bit、MSB first、软件 NSS、轮询传输。
- 不覆盖或修改参考资料 `407 LAN9252 Ethercat spi/`；只复制明确需要且许可允许随工程使用的 SSC 5.11 文件，并保留文件头和来源说明。
- 实验 Vendor ID `0x00F0C743` 仅用于本地台架，不得描述为 ETG 正式分配值。
- EEPROM 写入是显式人工停点。在 XML、固件、测试和构建全部一致之前，执行者不得写 EEPROM；到达停点后必须由用户确认并在 TwinCAT 中操作。
- 不用延长 TwinCAT 状态切换超时掩盖错误；每次失败记录 AL Status Code、LAN9252 驱动错误和 PDI/链路计数。
- 不使用动态内存、无界 Busy 循环、全局 `__disable_irq()` 或 ISR 内 SPI 访问。

## Review Focus

- 审查重点 1：所有错误和超时路径都释放 PA4/CS，且驱动绝不无限等待。
- 审查重点 2：ESI、SII、SSC 的身份、Mailbox、SM、PDO、字节顺序完全一致。
- 审查重点 3：`ETHERCAT_BRINGUP_ONLY=1` 下没有任何路径能够启动 PWM、DRV8323 或电机闭环。
- 审查重点 4：LAN9252 的 CSR 与 PRAM 对任意非对齐长度安全，尤其是 2 字节 RxPDO 和 6 字节 TxPDO。
- 审查重点 5：SSC 修改只限于硬件适配、应用选择和必要的编译兼容，不混入 F407 StdPeriph、OLED、蜂鸣器、ADC 或示例板逻辑。

- [ ] **Step 3: 定义最小、HAL 无关接口**

  使用固定宽度整数和 `size_t`：

  ```c
  typedef enum {
      LAN9252_OK = 0,
      LAN9252_ERR_ARGUMENT,
      LAN9252_ERR_IO,
      LAN9252_ERR_DIRECT_TIMEOUT,
      LAN9252_ERR_BYTE_TEST,
      LAN9252_ERR_READY_TIMEOUT,
      LAN9252_ERR_CHIP_ID,
      LAN9252_ERR_PDI,
      LAN9252_ERR_CSR_TIMEOUT,
      LAN9252_ERR_PRAM_TIMEOUT,
      LAN9252_ERR_EEPROM
  } LAN9252Status;

  typedef LAN9252Status (*LAN9252TransferFn)(void *context,
                                            const uint8_t *tx,
                                            uint8_t *rx,
                                            size_t length,
                                            uint32_t timeout_us);
  typedef struct {
      LAN9252TransferFn transfer;
      void (*select)(void *context);
      void (*deselect)(void *context);
      uint32_t (*time_us)(void *context);
      void *context;
  } LAN9252Transport;

  typedef struct {
      LAN9252Transport transport;
      LAN9252Status last_error;
      uint32_t timeout_count;
  } LAN9252Context;

  typedef struct {
      uint32_t byte_test;
      uint32_t id_rev;
      uint32_t hw_cfg;
      uint8_t pdi_control;
      uint16_t eeprom_status;
      uint8_t esc_type;
      uint8_t esc_revision;
      uint16_t esc_build;
      uint16_t al_status;
  } LAN9252ProbeResult;
  ```

  暴露：

  ```c
  void LAN9252_InitContext(LAN9252Context *ctx, const LAN9252Transport *transport);
  LAN9252Status LAN9252_ReadDirect(LAN9252Context *ctx, uint16_t address, uint8_t *data, size_t length);
  LAN9252Status LAN9252_WriteDirect(LAN9252Context *ctx, uint16_t address, const uint8_t *data, size_t length);
  LAN9252Status LAN9252_ReadEsc(LAN9252Context *ctx, uint16_t address, uint8_t *data, size_t length);
  LAN9252Status LAN9252_WriteEsc(LAN9252Context *ctx, uint16_t address, const uint8_t *data, size_t length);
  LAN9252Status LAN9252_Probe(LAN9252Context *ctx, LAN9252ProbeResult *result);
  ```

- [ ] **Step 4: 实现 Direct/CSR/PRAM 与探测**

  `address < 0x1000` 走 CSR，`address >= 0x1000` 走 PRAM。所有 16/32 位值通过显式 byte load/store 处理，不把非对齐缓冲区强转为整数指针。所有轮询以 `(uint32_t)(now - start) >= timeout` 判断回绕安全超时；统一 cleanup 释放 CS。
