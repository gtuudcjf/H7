# H743 电机控制工程代码精简设计

## 1. 目标

在不改变已通过实机验证的控制行为前提下，降低工程的代码量和理解成本。
保留现有分层结构、五种控制模式、保护、校准、双路 VOFA 遥测和必要的
Keil Watch 观测能力；删除只服务于历史调试、重复镜像或构建过程的内容。

本次修改以“控制路径更清楚”为目标，不以文件数量最少为目标。职责明确的
电流采样、坐标变换、PI、SVPWM、编码器和校准模块继续独立存在。

## 2. 不得改变的行为

- 模式 1：虚拟角度、电压开环。
- 模式 2：虚拟角度、Id/Iq 电流闭环。
- 模式 3：编码器电角度、Id/Iq 电流闭环。
- 模式 4：编码器速度 PI 加电流闭环。
- 模式 6：单圈位置 P、速度 PI 和电流闭环。
- TIM8、ADC、SPI4/DMA、DRV8323 和 USB/UART 的硬件配置与中断优先级。
- 10 kHz 电流环以及 1 kHz 速度环和位置环。
- 电流、速度、位置、编码器和功率级的现有参数、限幅与保护阈值。
- 电流零偏校准、编码器方向/零点校准和 Flash 保存流程。
- 故障锁存、停机、清故障和运行中模式切换语义。
- VOFA+ 的 8 通道顺序、JustFloat 格式、36 字节帧、100 Hz 周期，以及
  UART 和 USB 两路独立发送行为。

## 3. 精简后的调试观测

保留全局 `g_motor_control_debug`，使现有 Keil Watch/Ozone 调试方式继续可用，
但将其缩减为运行和故障定位真正需要的字段。字段按用途分组，避免继续镜像
控制器内部的每一个中间结果。

### 3.1 状态字段

- 当前模式 `mode`
- 请求模式 `requested_mode`
- 运行阶段 `run_state`
- 锁存故障 `fault`

### 3.2 电流与输出字段

- 两相 ADC 原始值 `phase_a_raw`、`phase_b_raw`
- 两相零偏 `phase_a_offset`、`phase_b_offset`
- `id_ref_a`、`id_a`、`iq_ref_a`、`iq_a`
- ADC 样本年龄 `adc_age_ticks`
- 过流确认计数 `overcurrent_count`
- 电压饱和标志 `voltage_saturated`

### 3.3 编码器字段

- 就绪与校准有效标志 `encoder_ready`、`encoder_calibrated`
- 原始单圈位置 `encoder_position_raw`
- 有效帧年龄 `encoder_age_ticks`
- 最近帧状态 `encoder_frame_status`
- CRC、帧、SPI 和超时累计计数
- 当前电角度 `electrical_angle_pu`

DMA guard 计数若仍参与现场硬件故障判断则并入上述错误计数；否则仅保留在
编码器模块内部，不再向控制层重复镜像。

### 3.4 速度与位置字段

- 速度命令 `speed_target_rpm`
- 送入速度 PI 的活动目标 `speed_active_target_rpm`
- 滤波速度反馈 `speed_filtered_rpm`
- 速度 PI 的 Iq 输出 `speed_iq_command_a`
- 速度 PI 饱和标志 `speed_pi_saturated`
- 位置目标、反馈和误差

最终字段数量可以因错误计数合并略有变化，但不得重新引入 PI 比例项、积分器、
Clarke/Park 中间量、原始编码器字节、收发 CRC 明细、启动检查点数组、前台调用
次数或参数副本。

## 4. 调试数据更新方式

删除覆盖全部内部状态的 `MotorControl_UpdateDebugState()`。关键字段在其数据产生
的位置更新：

- 状态转换时更新模式、运行阶段和故障；
- ADC 注入完成路径更新电流、原始 ADC、样本年龄和保护状态；
- 10 kHz 控制边界更新编码器、速度和位置状态；
- 校准完成时更新零偏和编码器校准有效状态。

不为了调试字段增加新的浮点计算，不在遥测前台重新执行控制算法。多字段 Watch
仍是逐字段观察，不承诺原子快照。

## 5. VOFA 遥测

遥测继续读取精简后的 `g_motor_control_debug` 中八个字段：

1. `id_ref_a`
2. `id_a`
3. `iq_ref_a`
4. `iq_a`
5. `speed_active_target_rpm`
6. `speed_filtered_rpm`
7. `position_target_deg`
8. `position_feedback_deg`

复制八个字段时保留当前短临界区，编码和异步提交仍在临界区外完成。
删除对外的 `g_motor_telemetry_debug`；发送端口的 busy、完成、丢帧和错误计数
继续作为遥测模块内部状态，用于实现非阻塞和独立端口语义。

## 6. 删除和简化范围

### 6.1 生产代码

- 删除 `motor_startup_trace.c/.h` 及其在 `motor_control.c` 中的状态和调用。
- 删除 `MotorControlDebug` 中未列入第 3 节的字段及相应赋值。
- 删除不再使用的旧名称兼容宏。
- 删除经全仓库引用检查确认没有调用方、且不属于 HAL 回调或对外控制接口的函数。
- 合并 `motor_control.c` 中语义完全一致的复位、限幅和安全退出片段；若合并会
  隐藏不同运行阶段的含义，则维持原结构。
- 精简重复、过时或仅描述历史开发过程的注释，保留硬件接线、时间基准、控制
  单位、状态转换、安全顺序和换硬件必须复核等关键注释。

不跨模块集中通用的短小 `Clamp`/`Wrap` 函数。它们属于各算法模块的边界保护，
强行共享会增加依赖，降低局部可读性。

### 6.2 测试

主机测试不进入 MCU 固件，因此不会为了减少固件体积而整体删除。保留以下测试：

- 电流采样、FOC/PI、开环、速度估算、速度 PI 和位置控制算法测试；
- BiSS 帧、DMA 缓冲、角度换算和编码器校准测试；
- Flash 校准记录测试；
- 运行策略、硬件配置、模式接线和 VOFA 帧/端口行为回归。

删除启动追踪单元测试；删除或改写要求旧调试字段、历史兼容宏存在的文本断言。
遥测适配测试改为只依赖保留的八个调试字段。

### 6.3 Keil 工程和构建产物

- 从 `emptytest.uvprojx` 删除已移除源文件。
- 删除 Git 当前跟踪的 Keil 可再生成中间文件，包括 `.o`、`.d`、`.crf`、`.map`、
  `.lst`、`.lnp`、`.htm` 和调试日志。
- `.axf` 与 `.hex` 也视为构建输出，不作为源码维护；若需要交付固件，应由正式
  发布流程重新构建并单独保存。
- 完善 `.gitignore`，保留 `.uvprojx`、必要的 `.uvoptx`、启动汇编、调试配置和
  CubeMX `.ioc`。

删除构建产物不影响 Keil 重新构建工程。

### 6.4 文档

更新当前使用文档中对 `g_motor_control_debug`、启动追踪和遥测调试全局变量的
说明。历史规格和计划保留作为设计记录，不逐项改写，也不把其中的旧接口描述
当作当前使用说明。

## 7. 可读性要求

- 函数名继续体现动作和对象，不引入单字母状态或含义不明的缩写。
- 状态机分支优先保持显式，避免以复杂宏压缩代码。
- 关键控制公式继续使用带物理单位的变量名。
- 每个关键注释解释“为什么有这个约束”，不重复翻译下一行代码。
- 删除代码后同步删除无效 include、声明、测试断言和工程项。
- 不在一次修改中顺带改变控制参数或重新整定算法。

## 8. 验证标准

完成修改后必须满足：

1. 全仓库搜索不存在 `motor_startup_trace`、`g_motor_telemetry_debug` 和已删除的
   调试字段引用。
2. 精简后的 `g_motor_control_debug` 包含第 3 节要求的现场观测值。
3. VOFA 仍输出相同的八个通道、36 字节帧和 10 ms 周期。
4. 所有保留的主机单元测试和配置/集成回归通过。
5. Keil 工程不引用已删除文件，并完成一次全量编译，结果为 0 error、0 warning。
6. 对照修改前后确认 `motor_params.h`、TIM8、ADC、SPI4、DRV8323、中断优先级、
   模式枚举和故障枚举没有意外变化。
7. `git diff --check` 通过，工作区只包含本设计范围内的修改。

软件测试与编译用于证明结构和接口没有明显回归；最终实机确认至少检查默认速度
模式启动、正反向低速、电流反馈、编码器错误计数和 UART/USB VOFA 波形。实机
验证由使用者在安全供电和机械条件下执行。
