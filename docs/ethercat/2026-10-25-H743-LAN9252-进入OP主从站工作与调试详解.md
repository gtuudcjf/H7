## 一、先明确：进入 OP 到底证明了什么

OP 是 Operational，表示 EtherCAT 应用层状态机进入运行态。它不是某个 GPIO 的状态，不是电机算法编号，也不是“主站软件已经打开”。

本项目正常路径为：

```text
上电、配置装载与初始化
          │
          ▼
        INIT ──► PREOP ──► SAFEOP ──► OP
                   │          │          │
                 邮箱可用   输入更新   输出也可由应用接收处理
```

主站通常发起状态请求；从站核查对应条件后确认状态，不能把“点击请求 OP”当成“实际已到 OP”。状态机的一般规则可核对 [Beckhoff ESM 说明](https://infosys.beckhoff.com/content/1033/el15xx/1036980875.html)。

### 1.1 五类证据不能互相替代

| 证据 | 可以说明 | 不能单独说明 |
|---|---|---|
| 网口 Link 正常、能扫描到设备 | 网线与部分 LAN9252 硬件链路有响应 | MCU 已运行、邮箱已工作、已 OP |
| SPI `BYTE_TEST` 正确 | 该次主机接口读取正确 | 持续 SPI 访问可靠、SSC 未停服 |
| PREOP 在线 CoE 身份可读 | 邮箱、对象字典服务链路正在工作 | 周期任务已启动、PDO 正常 |
| 从站实际 OP，且过程数据工作计数有效 | 本轮周期通信具备运行条件 | 电机已使能、实际转速准确 |
| 电机在正给定 6、12 时能旋转 | 已有本轮功能反馈 | 反向、噪声改善、采样准确性、长期安全或实时认证 |

### 1.2 进入 OP 的建议判据

不要只看一个绿色图标。至少组合核对：

- 选中正确的物理从站，Current State 为 OP；Requested State 也为 OP。
- 从站原始 `AL Status & 0x000F == 0x0008`，AL 错误位未置，`AL Status Code=0`。
- TwinCAT 的完整 `InfoData.State` 无异常标志；当前 PLC 采用严格的 `State=8` 检查。
- 对应过程数据 `WcState=FALSE`，主站确实在发送 Cyclic 帧。
- MCU 无 SPI 访问故障锁存，SSC 持续服务。
- 当前电机版在不启动电机的情况下，`CommandSequence` 和 `AcceptedSequence` 持续推进。

最后一项不是 EtherCAT 标准强制的 OP 条件，而是本项目用于检查 PLC→PDO→MCU 命令链路的补充证据。电机版待机时 `CycleCounter=0` 可以完全正常。

### 1.3 本工程已经有的实机证据

10-15 首次通信版记录了实际 OP、`State=8`、`WcState=0`、`CycleCounter=2127`；10-20 至 23 电机联调又取得正向给定 6、12 可旋转的用户反馈。它们是不同版本、不同阶段的证据，不应将通信版截图的 revision、PDO 长度或状态字直接用于当前电机版。

## 二、系统组成：主站、LAN9252 与 MCU 分别做什么

```text
PC / TwinCAT
  ├─ ESI：知道设备身份、邮箱、PDO 和支持的功能
  ├─ EtherCAT Master：扫描、配置、发周期帧、请求状态、检查 WKC
  └─ PLC / I/O Task：准备输出、消费输入、应用启停和故障逻辑
                │ 网线：EtherCAT 帧
                ▼
LAN9252 / ESC
  ├─ PHY、EtherCAT 报文处理
  ├─ EEPROM 配置装载
  ├─ FMMU：逻辑过程映像与本地物理区的映射
  ├─ SyncManager：邮箱/过程数据的一致性交换
  └─ 寄存器和过程 RAM
                │ SPI1 / PDI
                ▼
STM32H743
  ├─ LAN9252 驱动：Direct / CSR / PRAM 访问
  ├─ SSC：处理 AL 请求、邮箱、CoE 和 PDO
  ├─ 应用映射：把字节流与应用字段连接
  └─ 电机桥接与控制：只有另外满足许可才可能打开功率输出
```

### 2.1 主站负责

1. 使用正确网卡与驱动建立 EtherCAT 设备。
2. 识别从站身份，将实际拓扑与工程配置对应起来。
3. 根据 ESI/在线信息配置邮箱、过程数据区、FMMU、启动参数等。
4. 提供真实周期源，连续发送过程数据，而不是只发扫描和寄存器读请求。
5. 写入 AL Control 状态请求，等待从站实际响应，并检查状态码和工作计数。
6. 在运行时检测失联、工作计数异常、CRC、丢帧与状态下降。
7. 由 PLC 决定应用行为；OP 本身不应等于“自动启动电机”。

### 2.2 LAN9252 负责

LAN9252 处理 EtherCAT 物理链路及 ESC 数据交换，向 MCU 暴露 PDI 接口。本项目用 SPI1 访问它，不是 STM32 自身使用以太网 MAC/TCP/IP 直接运行 EtherCAT 从站。

LAN9252 能通过网口响应部分寄存器请求，不意味着 MCU 已经运行 SSC。反过来，MCU 的 `uwTick` 在增长，也不意味着 LAN9252 的 EtherCAT 状态机仍被应用正确服务。

### 2.3 MCU / SSC 负责

1. 初始化 MCU、SPI、计时和安全输出状态。
2. 检查 LAN9252 身份、Ready、PDI、EEPROM 装载条件。
3. 初始化 SSC 的状态机和对象字典。
4. 持续读取事件、处理 AL 请求和邮箱响应。
5. 在转换时核对 SM 配置、映射长度及同步条件，接受或拒绝状态请求。
6. 在有效交换条件下读取主站输出，生成从站输入。
7. 出错时保留证据、撤销应用输出资格；不能让旧命令在重连后自动恢复危险运动。

### 2.4 ESM 的“安全态”不是功能安全认证

SAFEOP 的名称不能直接理解为认证安全停机。本工程还依赖应用回调、功率许可、驱动使能和 PWM 输出控制。软件写了禁能位也不等于已经测量到硬件断开，更不等于机械轴瞬间停稳。

## 三、先确认版本：不要混用历史通信版和当前电机版

### 3.1 两套设备布局

| 项目 | 首次 OP 通信版 | 当前电机 / OpenAngle 版 |
|---|---|---|
| 固件选择 | `ETHERCAT_BRINGUP_ONLY=1`，`MOTOR_CONTROL=0` | `BRINGUP_ONLY=0`，`MOTOR_CONTROL=1` |
| Revision | `0x00000001` | `0x00000002` |
| ESI | `EtherCAT/H743-LAN9252-LAB.xml` | `EtherCAT/motor/H743-LAN9252-MOTOR.xml` |
| 主站输出 / 从站 RxPDO | 2 B | 8 B |
| 主站输入 / 从站 TxPDO | 6 B | 20 B |
| 应用语义 | 控制字 bit0 回显、应用计数 | 控制字、速度、序号、故障与控制反馈 |
| 默认输出策略 | 不进入电机启动路径 | 上电不自动启动；还受功率宏、心跳、故障等约束 |

两版名称都可能显示 `H743-LAN9252-LAB`，因此不能只凭设备名称区分。应核对 revision、PDO 长度、固件宏和在线 `0x1018`。

### 3.2 当前电机构建的区别

| 构建入口 | 关键特征 | 仅检查 OP 时的注意事项 |
|---|---|---|
| `ethercat_openangle.uvprojx` / `OpenAngleDryRun` | `OPEN_ANGLE=1`，`POWER_ENABLED=0` | 功率锁定；Start 被拒绝不等于 OP 失败 |
| `OpenAngleBenchCheck` | `OPEN_ANGLE=1`，`POWER_ENABLED=1` | AXF 可被下载且允许申请功率；只为检查 OP 不发送 Start |
| `ethercat_motor.uvprojx` 默认 DryRun | 编码器速度版、功率锁定 | 不要与 OpenAngle PLC 的 profile 语义混用 |
| `LocalMotor` | 旧本地运行路径 | 可能上电自动启动，不能当作无输出通信验证固件 |

功率宏的默认锁定与 OpenAngleBenchCheck 的显式使能并不矛盾；应看实际被下载 AXF 的构建配置，不能只看公共头文件默认值。

### 3.3 三种容易混淆的“运行/FreeRun”

| 名称 | 所在层 | 含义 |
|---|---|---|
| 从站 FreeRun 同步方式 | SSC / EtherCAT 从站 | 当前不按 SM IRQ 或 DC Sync 信号调度应用，采用轮询服务 |
| TwinCAT `Toggle Free Run State` | 主站 Config Mode | 没有 PLC 任务时，由 I/O 驱动提供周期通信 |
| PLC / TwinCAT Runtime Run | 主站运行环境 | PLC 任务执行并可驱动周期 I/O；不等于 MAIN 中的 `bStart=TRUE` |

本工程从站使用 FreeRun，不代表主站自动开始发送周期帧。当前从站的 `DC_SUPPORTED=0`、`AL_EVENT_ENABLED=0`、`INTERRUPTS_SUPPORTED=0`。不要因为 LAN9252 芯片支持 DC，就在当前应用中启用 DC 同步。

## 四、配置一致性：进入 OP 之前必须一致的几份资料

### 4.1 ESI、SII、对象字典、PLC 分别在哪里

| 配置 | 保存位置 | 作用 | 修改后影响 |
|---|---|---|---|
| ESI XML | PC 的设备描述目录及仓库 | 告诉主站设备如何识别和配置 | 需要重载描述，核对工程是否实际引用新版 |
| SII 二进制 | 板上外部 EEPROM | 提供上电配置、身份、邮箱和类别等 | 写入后须核对回读并真正重启 LAN9252 |
| SSC 对象字典和尺寸宏 | MCU 固件 | 运行时提供 CoE 对象、映射与应用数据长度 | 需要重新构建并由操作者下载固件 |
| TwinCAT I/O 配置 | XAE 系统工程 | 网卡、从站、SM/FMMU、任务、链接等 | 修改后通常需要检查并重新激活配置 |
| PLC 声明/程序 | PLC 工程 | 变量类型、按钮逻辑、序号和控制字 | 需编译、下载及运行，不能只改离线源文件 |

将 XML 放到电脑上不会自动修改 EEPROM。EEPROM 下载也不会替换 H743 程序。更新 PLC 源文件不会自动更新已经运行的 PLC 程序。

### 4.2 当前电机版身份目标

| 字段 | 当前代码 / ESI 目标 |
|---|---|
| Vendor ID | `0x00F0C743`，仅本地实验，不是 ETG 正式分配 |
| Product Code | `0x00009252` |
| Revision | `0x00000002` |
| Serial Number | 固件目标 `0x00000001`；实际 EEPROM 需以回读为准 |
| 设备类型名 | `H743-LAN9252-LAB` |
| PDI Control | 项目要求低字节 `0x80` |
| SII 配置目标有效大小 | 2048 B，不表示物理 EEPROM 只有该容量 |

历史身份记录曾出现 EEPROM 截图序列号与在线 CoE 序列号尚需完整回读复核的事项。不能因已到 OP 就反推全部身份字段必然一致。

`candidate-manifest.json` 中的 `hardware_verified=false`、`write_authorized=false` 是候选镜像状态。实际板子能 OP，不会自动证明仓库候选 BIN 就是板上现有内容；也不能仅为整理文档改写这些标志。

### 4.3 当前电机版 SM 区域

| SM | 起始地址 | 默认长度 | 方向（以主站为参照） | 控制字节 |
|---|---:|---:|---|---:|
| SM0 | `0x1000` | 128 B | 主站发邮箱，从站收 | `0x26` |
| SM1 | `0x1080` | 128 B | 从站发邮箱，主站收 | `0x22` |
| SM2 | `0x1100` | 8 B | 主站过程输出，从站 RxPDO | `0x64` |
| SM3 | `0x1400` | 20 B | 主站过程输入，从站 TxPDO | `0x20` |

通信版只有 SM2/3 的默认长度不同，分别为 2/6 B。邮箱 128 B 包含 6 B 邮箱头，不是可以使用 128 B 的有效负载。当前 ESI 声明邮箱最小值 34 B、最大值 128 B，不能把该范围和当前默认配置混为一谈。

这些是本工程固定布局，不是所有 EtherCAT 从站都必须使用的地址。

### 4.4 PDO 映射应对应

```text
0x1C12:01 → 0x1600 → SM2 / RxPDO
0x1C13:01 → 0x1A00 → SM3 / TxPDO
```

本项目固定映射不是要求主站每次都动态写入映射对象。主站根据描述建立配置；对象可只读，上线读取核对即可。不要在 Startup 列表里盲目加入写 `0x1600/0x1A00/0x1C12/0x1C13` 的命令，或使用不支持的 Complete Access、分段 SDO、FoE。

### 4.5 ESI 安装与 SII 写入的边界

- ESI 应装入本机实际 XAE 使用的设备描述目录；常见 TwinCAT 3 路径为 `C:\TwinCAT\3.1\Config\Io\EtherCAT`，安装方式不同需以实际环境为准。
- 安装后重载设备描述或重开 XAE，并核对选中的 revision；扫描成功不保证选中了正确的自定义 ESI。
- 不将临时 OnlineDescription 当成已核对的设备描述，不通过随意删除整个缓存目录解决身份问题。
- SII 写入不是日常进入 OP 的步骤。已正常工作的 EEPROM 不必重复写入。
- 确需写入时，先确认唯一目标、读取并保存现有内容和散列，核对候选身份、校验和布局，由操作者明确批准写入；写完回读比较，再完整断开 LAN9252 逻辑电源并重新上电。避免 ST-LINK、USB 或其他接口反向供电导致未真正重启。
- ESI、SII 与固件必须兼容；EEPROM 更新后需要硬件重启，参见 [ESI 管理说明](https://infosys.beckhoff.com/content/1033/ethercatsystem/1036998411.html) 及 [TwinCAT EEPROM Update 说明](https://infosys.beckhoff.com/content/1033/tc3_io_intro/1446518411.html)。

## 五、主从站协作的总时序

```text
主站 / TwinCAT              LAN9252 / ESC                 H743 / SSC
     │                          │                            │
     │                     上电装载 EEPROM                MCU 初始化
     │                          │                      SPI probe、MainInit
     │── 扫描、寄存器访问 ──────►│                            │
     │◄─ 拓扑、身份、状态 ───────│                            │
     │                          │                            │
     │── 配置邮箱、请求 PREOP ─►│── AL 事件 / SPI 读取 ──────►│
     │                          │◄─ 邮箱检查、AL 状态应答 ────│
     │◄─ 实际 PREOP ────────────│                            │
     │── 在线 CoE / 身份读取 ──►│◄──── 邮箱处理与响应 ────────│
     │                          │                            │
     │── 配置过程区、FMMU ─────►│                            │
     │── 请求 SAFEOP ──────────►│◄──── 映射/SM/同步检查 ──────│
     │◄─ 实际 SAFEOP、输入数据 ─│◄──── 开始输入更新 ──────────│
     │                          │                            │
     │── 有效周期输出、请求 OP ►│── SM2 事件 ────────────────►│
     │                          │◄─ 收到首帧、允许输出更新 ──│
     │◄─ 实际 OP ───────────────│                            │
     │                          │                            │
     │── 持续 RxPDO / 序号 ────►│── SPI 读过程 RAM ─────────►│
     │◄─ 持续 TxPDO / 反馈 ─────│◄─ SPI 写过程 RAM ──────────│
```

该图是职责和依赖示意，不是强制要求每台主站逐条按图中顺序发一帧。实际配置可能批量进行，状态请求与首次输出等待也可能交错。关键是完成状态确认所需的条件。

尤其不要设计成“必须看到 OP 后主站才开始周期输出，而从站又等首帧输出才肯确认 OP”。本 SSC 的 SAFEOP→OP 包含等待首帧输出的 pending 流程，必须由有效周期源打破这个等待。

## 六、每一级状态：主站要做什么，从站要做什么

### 6.1 上电至 INIT：先建立可服务的从站

**主站侧：**

1. 找到实际连接的网卡和物理端口，确认从站数量、顺序和身份。
2. 能通过网络读取 ESC 基础寄存器，并不要求此时 PDO 已经工作。
3. 保留原始身份、EEPROM 和状态信息，不先忽略 identity mismatch。

**从站侧：**

1. LAN9252 完成电源、复位、时钟与 EEPROM 装载。
2. MCU 完成时钟、GPIO、SPI1 与时间基准初始化。
3. `HW_Init()` 初始化驱动上下文并执行 `LAN9252_Probe()`。
4. `EtherCAT_Init()` 调用 `MainInit()` 注册对象、初始化 SSC。
5. 进入主循环，持续调用 `EtherCAT_Service()`；仅初始化成功后不再服务，无法完成后续状态请求。

**应观察：**

- 新一轮初始化后 `ethercat_init_status=1`，probe 各字段符合当前配置。
- `last_driver_error=0`，`spi_timeout_count=0`；首次故障结构通常 `valid=0`。
- 原始 AL 状态低四位为 1，错误码正常为 0；尚未刷新或 probe 提前失败时不能解释未读取字段。
- MCU 的 `uwTick` 持续增长；软件输出仍保持禁能。

**常见误判：**“Memory Working Counter=1，所以 MCU 从站程序已运行”。该值只能说明本次网络访问，不能证明 SPI/PDI/SSC 链路。

### 6.2 INIT→PREOP：建立邮箱通信

**主站侧：**

1. 按匹配描述配置 SM0/SM1 邮箱地址、大小、方向及启用状态。
2. 请求 PREOP，并轮询 Actual State / AL Status Code。
3. 成功后用在线 CoE 读取对象，确认不是只展示离线 ESI 默认值。

**从站侧：**

1. SSC 读取 AL 请求，进入 `AL_ControlInd()`。
2. `CheckSmSettings()` 检查邮箱配置，核对区域、长度、方向等。
3. 检查 EEPROM 装载状态，启动 `MBX_StartMailboxHandler()`。
4. 调用 `APPL_StartMailboxHandler()`；本工程回调首先清理应用交换状态，不启动电机。
5. 成功后邮箱运行，更新 AL 状态；失败时回报状态码或保持原状态。

**应观察：**

- 实际 PREOP，原始低四位为 2，无错误位，AL Code=0。
- `bMbxRunning=TRUE`，在线 `0x1018:01..04` 能获得实际响应。
- `bEcatInputUpdateRunning`、`bEcatOutputUpdateRunning` 正常不应当按 OP 解释。
- PREOP 不要求电机版 `CycleCounter` 增长，也不要求 `AcceptedSequence` 推进。

读取 `0x1018` 时分别核对 Vendor、Product、Revision、Serial。设备名称相同不等于身份四字段一致。

### 6.3 PREOP→SAFEOP：配置并启动过程输入

**主站侧：**

1. 根据 ESI 配置 SM2/SM3，建立 FMMU 和任务过程映像。
2. 核对 PDO assignment、映射的类型、位宽和字节总数。
3. 确认当前从站使用 FreeRun，无错误的 DC/SM 同步启动配置。
4. 启动能够实际发帧的 I/O 周期源，再请求 SAFEOP。

**从站侧：**

1. `APPL_GenerateMapping()` 返回本次构建的输入/输出长度。
2. SSC 检查全部相关 SM 配置；`StartInputHandler()` 检查过程 RAM 区域与邮箱是否重叠，并读取 SM2/3 地址。
3. 检查同步配置：本应用明确不支持的 DC/SM 同步不能通过任意勾选启用。
4. 调用 `APPL_StartInputHandler()`，允许输入更新，置 `bEcatInputUpdateRunning=TRUE`。
5. 主站能周期读取从站输入，但应用输出仍不按正常 OP 处理。

**应观察：**

- 实际 SAFEOP，低四位为 4、AL Code=0。
- 当前电机版 `nPdOutputSize=8`，`nPdInputSize=20`。
- `nEscAddrOutputData=0x1100`，`nEscAddrInputData=0x1400`。
- `bEcatInputUpdateRunning=TRUE`，输出更新未完成使能。
- 即使能看到输入映像，其中应用字段仍可能为零、停机标志或旧快照；要看项目发布条件。

SAFEOP 的定义不是“电机已经安全使能”，也不是“当前反馈均为有效物理测量”。

### 6.4 SAFEOP→OP：必须有有效周期输出

**主站侧：**

1. 主站达到足以支持从站目标状态的运行条件。
2. 周期任务或 Config Mode FreeRun 已实际发帧。
3. 向 SM2 发送长度正确的周期输出；有效输出可以是禁能和零需求，不需要非零速度。
4. 请求 OP，等待从站完成确认；核对从站 Current State，不只看 Requested State。

**从站侧：**

1. `StartOutputHandler()` 可以先返回 `NOERROR_INWORK`，暂缓确认。
2. `MainLoop()` 轮询到 `PROCESS_OUTPUT_EVENT` 时，置 `bEcatFirstOutputsReceived=TRUE`。
3. `AL_ControlRes()` 在非 DC 路径检查首帧输出条件，调用 `APPL_StartOutputHandler()`。
4. 成功后置 `bEcatOutputUpdateRunning=TRUE`，更新 AL 状态为 OP。
5. 后续输出映射才将周期命令交给电机桥接；OP 本身没有调用 `MotorControl_Start()`。

**应观察：**

- Cyclic 发送帧数增长、帧率非零；WKC 与该过程数据命令的期望值匹配。
- `bEcatFirstOutputsReceived=TRUE`，输入和输出更新标志均为 TRUE。
- 原始 AL=8、Code=0；TwinCAT 正常完整 `State=8`、`WcState=FALSE`。
- 无新的 SPI 首故障。进入 OP 后仍需持续服务，不是一次握手结束就可以暂停 MCU。

### 6.5 OP 中：传输有效和命令有效仍是两层

应用认定有效交换的条件为：

```c
bEcatInputUpdateRunning &&
bEcatOutputUpdateRunning &&
bEcatFirstOutputsReceived &&
!HW_AccessFault()
```

电机命令在该条件成立后还要检查 profile 确认、控制字合法性、新序号、速度范围及启动条件。因此从站可以 OP，但电机保持禁能或锁存应用故障；这不应直接归因于 EtherCAT 状态转换失败。

### 6.6 向低级状态转换

- OP→SAFEOP：停止正常输出处理，应用撤销运行资格。
- SAFEOP→PREOP：停止过程输入更新，保留适用的邮箱服务。
- PREOP→INIT：关闭邮箱并清理有关资源。
- 断线、看门狗和本地错误也可能触发降级。状态返回后不等于旧运动命令可以继续执行。

## 七、当前工程的代码执行链与关键入口

### 7.1 初始化与轮询

```text
main()
 ├─ MPU / HAL / SystemClock_Config
 ├─ GPIO / SPI1；电机版还初始化必要的 ADC / SPI2 / TIM
 ├─ EtherCAT_Init()
 │   ├─ HW_Init()
 │   │   ├─ LAN9252_BoardTransport()
 │   │   ├─ LAN9252_InitContext()
 │   │   └─ LAN9252_Probe()
 │   └─ MainInit()
 │       ├─ ECAT_Init()
 │       └─ COE_ObjInit()
 └─ while (1)
     ├─ EtherCAT_Service()
     │   └─ MainLoop()
     └─ EtherCATMotorBridge_Service()  // 仅电机网络分支
```

`MainLoop()` 包含事件轮询、PDO 映射、应用、定时补处理、`ECAT_Main()`、`COE_Main()` 和错误检查。一次主循环不必与主站一次 PLC 周期一一对应。

### 7.2 三类 LAN9252 访问

| 访问 | 典型内容 | 代码 |
|---|---|---|
| Direct 主机寄存器 | `BYTE_TEST`、`HW_CFG`、`ID_REV`、CSR/PRAM 命令窗口 | `direct()` / `LAN9252_ReadDirect()` |
| CSR 间接 ESC 寄存器 | AL Control/Status、AL Event、SM 配置等 | `csr()` |
| PRAM FIFO | 邮箱和周期过程数据 | `pram()` |

上层 `HW_EscRead/Write()` 通过逻辑 ESC 地址选择 CSR 或 PRAM。SPI 保持串行前台访问，不在 TIM8/ADC 控制中断里调用；名称带 `Isr` 的 SSC 兼容别名，不表示本工程启用了 ESC 中断。

### 7.3 故障锁存与停服

`lan9252_port.c` 保留首个端口访问错误。`EtherCAT_Service()` 发现访问错误时：

1. 将内部服务状态改为 `ETHERCAT_STATUS_LAN9252_ERROR`。
2. 调用 `APPL_AckErrorInd()` 清理/撤销应用交换。
3. 记录已有过程数据与端口诊断。
4. 后续调用不再继续正常 `MainLoop()`。

**这时 MCU 的 while 循环和 `uwTick` 可以继续运行，但 SSC 已经停服。** LAN9252 网口也可能仍有响应，所以不能只看 CPU 活着、网口灯亮或之前的 PREOP 就认为从站健康。

`ethercat_init_status` 只是 `EtherCAT_Init()` 的返回副本，不会在后续停服时自动改成错误。应结合 `last_driver_error`、首次快照、主站实际状态一起判断。

## 八、进入 OP 前的硬件、供电与 PC 准备

### 8.1 台架安全与供电

本板的 CPU 与电机功率侧不能按现有条件分开供电。不要照搬早期手册中“在硬件允许时断开动力母线”的前提，把不存在的隔离方式当作已经实现。

- 任何更改 U/V/W、抱闸、探头或跳线前先断电，并确认储能释放，禁止带电插拔电机线。
- 只检查 OP 不需要电机转动，不发送 `bStart`，不提高电流或速度。
- 当前实验使用过 24 V、1 A 电源限流；这是台架设置，不是电机相电流额定值或硬件安全保证。
- CPU 同时给功率侧上电时，保持经过核对的禁能路径；软件功率锁不替代电气核查。
- 电机若已连接，保持固定、空载、轴周围无障碍，准备可靠断电手段。
- 外接抱闸 12 V 与电机 24 V 母线不能混接；OP 检查不依赖释放抱闸，但若之后启动电机必须按正确方式释放。
- PC4 输出寄存器和 `MOE` 是软件证据；实际驱动禁能效果还取决于原理图、PCB、引脚状态及外部电路。不能只凭注释判断 PB5/PC4 等硬件信号的真实作用。

### 8.2 网络连接

- 用专用网卡连接从站 IN 端口；名称和端口对应以板卡为准，不按照片猜测。
- 首次单板直连，减少普通交换机、路由器、虚拟交换机和办公网络的干扰。
- EtherCAT 过程数据不是普通 TCP/IP 会话；能 ping 通、IP 同网段不是本项目进入 OP 的核心判据。XAE 到目标机的 ADS 连接则是另一层问题。
- 区分“XAE 连不上 TwinCAT Target”和“EtherCAT 主站连不上从站”；先明确出问题的是哪一段。

### 8.3 主机环境

1. 核对实际 TwinCAT 目标、本机或远程系统，以及正确网卡。
2. 通过兼容网卡页面核对驱动绑定；路径可能为 `TwinCAT → Show Real Time Ethernet Compatible Devices` 或设备 Adapter 页的 `Compatible Devices...`。
3. 记录 TwinCAT Build、Windows 环境、网卡型号与驱动分类。历史截图存在不同 Build，不能把旧报告版本当成今天实际版本。
4. 标记为 demo 的网卡只能支持相应实验结论，不因一次 OP 就变成正式实时平台。
5. 若系统提示实时核、驱动或虚拟化配置问题，按实际错误和官方文档处理；不要为普通 OP 故障盲目关闭 Windows 安全功能，也不要导入历史 `.reg` 备份。

网卡驱动操作属于主机配置变更，不是本文自动执行步骤。入口可核对 [Beckhoff 实时驱动安装](https://infosys.beckhoff.com/content/1033/el26xx/1036996875.html)。

## 九、Keil：下载、连续运行和 Watch 的正确使用

### 9.1 下载之前

- 核对实际工程、Target、宏、输出路径和 AXF 时间/散列。
- `OpenAngleBenchCheck` 与 DryRun 名称相似，功率权限不同；AXF 没有配套 HEX 不表示不能下载或没有功率风险。
- 只构建不等于已更新板上固件，Watch 的符号也必须来自当前 AXF。
- 固件下载可能涉及 Flash 擦除。工程预留校准区不代表下载器不会整片擦除；不得顺手 Whole Chip Erase。
- 不为方便 OP 自动删除或覆盖操作者的 `.uvoptx`、ST-LINK 和启动设置。

### 9.2 本项目已观察到有效的调试顺序

1. 如确需更新程序，由操作者先完成下载。
2. 进入 Debug，清除会在初始化、SPI、主循环反复命中的测试断点。
3. 按 F5 / Run，使 MCU 连续运行。
4. 启用 `View → Periodic Window Update`，观察 `uwTick` 增长和初始化结果。
5. 确认连续运行后，再在 TwinCAT 请求状态、运行 PLC 和交换指令。

用户曾反馈“先进入 Debug 并运行，再在 TwinCAT 操作就没有问题”。应理解为保证当前固件连续执行的有效顺序，不能解释成 EtherCAT 协议要求一定连接调试器。脱离调试器能否正确冷启动，属于另外的启动验收。

### 9.3 为什么调试器会导致 OP 掉线

- 进入 Debug 可能复位 MCU，并停在 `main()` 入口，此时 SSC 尚未服务。
- 暂停、单步、Reset、重新下载会打断邮箱或过程数据处理；如果在 SPI 片选低期间停住，还会打断事务。
- LAN9252 未必与 MCU 同步复位，主站可能先看到旧状态，再超时或下降。
- 恢复后 `OP→INIT`、Frame missed、心跳故障、`nPhase=90` 可能是本次调试操作的后果，不必然是新的硬件故障。
- TIM6 也是 MCU 中断，不保证 CPU 被暂停时还能执行撤销输出；带动力运行时不得用暂停 MCU 代替停机。

### 9.4 Watch 使用注意事项

- 黄色执行箭头、寄存器 PC 在连续运行时可能是上次暂停的显示；不能仅凭它们判定复位或卡在入口。
- `uwTick` 连续增长是 CPU 存活证据，不是 SSC 服务正常的充分条件。
- 运行中结构体多字段不是天然原子快照；判断历史首次故障先看 `valid=1`。
- 只读已有变量，不在 Watch 中调用会访问硬件的函数，也不修改内部状态来“清错”。
- 避免周期读取 SPI `RXDR/TXDR` 等带副作用的数据寄存器；不要清外设标志或写 AL 寄存器强行改状态。
- 如实时刷新明显干扰，减少 Watch 项或降低刷新频率；不在运动中使用断点抓取“稳定数据”。

## 十、TwinCAT：两条进入 OP 的操作路线

### 10.1 选择路线，避免混搭

| 路线 | 适用情况 | 周期源 |
|---|---|---|
| A：Config Mode / FreeRun | 首次单独确认通信和逐级状态，不依赖 PLC 运行 | I/O FreeRun |
| B：Run Mode / PLC | 当前电机工程正常使用，核对 PLC 指令和应用链路 | 实际运行的 PLC / I/O 同步任务 |

两条路线都需要 MCU 持续运行。仅检查 OP 时，不必创建 NC 轴；本项目不是 CiA402 驱动器，也不需要为 OP 加入运动控制配置。

### 10.2 路线 A：Config Mode 下首次通信检查

1. 确认物理从站和固件版本，保持无启动命令；电机版不发送 Enable。
2. 核对 ESI 已安装，使用正确网卡扫描；若已有工作工程，不为每轮测试重新扫描和重建链接。
3. 确认 DC 关闭、从站同步方式为 FreeRun，先使用与工程相符的较宽周期。首次通信历史建议 10 ms；数值要从实际任务/主站配置核对，不能按 UI 刷新速度推断。
4. 检查父节点 EtherCAT 设备，例如历史 `Device 2`，不要只点子节点 `Box 1`。
5. 在 Advanced Settings 的 State Machine / Master Settings 中查看 Startup State，以及 `Stay at PRE-OP until Sync Task started`。
6. 按首次调试采用过的方式，可暂以 SAFEOP 为启动目标，然后在 Config Mode 启动 `Toggle Free Run State`，使 Cyclic 帧实际运行。
7. 该命令是开关，不要连点；若之前处于 Run Mode，官方说明要求先 Reload Devices，再开启相应 FreeRun。
8. 在主站 Online 页确认 Cyclic 计数增长、Frames/sec 非零；Queued 有收发不能替代这一步。
9. 从 INIT、PREOP、SAFEOP 逐级请求并记录，最后请求 OP，再查看具体从站的实际状态。
10. 保持零需求和禁能，不为证明 OP 去点击电机 Start。

路线 A 的电机版即使没有有效 PLC 序号，也可能达到 EtherCAT OP；但应用 Ready、心跳和启动许可不能据此验收。

### 10.3 路线 B：当前 PLC 工程正常运行

1. 核对当前为 revision 2、8/20 B 布局，PLC 为 OpenAngle 对应版本。
2. 核对目标系统、适配器和过程数据链接。当前 GVL 有 13 个映射变量：11 个应用 PDO 字段，加 `State`、`WcState` 两个主站诊断字段。
3. 检查 PLC Task 实际调用 `MAIN`，项目提供的 `PlcTask.TcTTO` 周期为 `10000 μs`，即 10 ms；活动工程以实际配置为准。
4. 在进行激活、下载、登录等操作前，确认电机停机且不会因保留的强制值启动。
5. 初始化操作量：`bStart=FALSE`、`bStop=FALSE`、`bDisable=FALSE`、`bReset=FALSE`、`bFreezeHeartbeat=FALSE`，`rDemandRpm=0`。
6. 确认 MCU 已 F5 连续运行，再按实际工程执行配置激活、PLC 登录/下载与运行。只编译成功或只登录不等于 PLC 周期正在执行。
7. 在主站页确认实际 OP 和周期帧；在 PLC 看 `State=8`、`WcState=FALSE`。
8. 观察 `CommandSequence` 和 `AcceptedSequence` 随时间前进，`ControlWord=0x0100`、`TargetSpeed=0`。
9. 如电机应用锁存故障，先确认通信健康和输出已关闭，再按下节复位；不要为清应用故障重新写 EEPROM。

`PLC Start/Run` 是运行程序；`MAIN.bStart` 才是应用启动请求。前者不应与后者混为一谈。

### 10.4 主站状态请求的位置与限制

- Device Online 页上方的 Init/Pre-Op/Safe-Op/Op 按钮，作用于所选主站设备。
- 从站行的右键 `Request ... state`，作用于具体从站。
- 若报 `Master state PREOP is insufficient`，先解决父主站和周期源，不是在从站按钮上反复点 OP。
- 检查是否有从站独立 Final State 上限、Disabled、忽略/模拟等设置，不通过设置不存在的从站为可选来掩盖问题。
- Startup State 是目标策略，不是达到状态的证明。主站可以配置为在同步任务开始前保持 PREOP。

主站等待任务和通信后重新初始化策略可核对 [Master Settings](https://infosys.beckhoff.com/content/1033/tc3_io_intro/1446524555.html)；Config Mode 无 PLC 周期的用法见 [Toggle Free Run State](https://infosys.beckhoff.com/content/1033/tc3_userinterface/2954025611.html)。

## 十一、调试观察：从最小集合到深入定位

### 11.1 日常最小观察集合

不必一次展开全部结构。优先保持：

```text
TwinCAT：Master Actual State、Box Current/Requested State、State、WcState
         Cyclic 帧数/帧率、当前 AL Status Code
PLC：    bHealthy、nPhase、CommandSequence、AcceptedSequence
Keil：   uwTick、ethercat_init_status、*ethercat_diagnostics
         g_lan9252_first_fault.valid、g_lan9252_hal_fault.valid
```

在电机版待机时，加看 `ControlWord`、`TargetSpeed`、`MotorFault`、`BridgeFault` 和 `bElectricalOutputOff`。这些已足够判断大多数“通信正常但应用不就绪”的问题。

### 11.2 TwinCAT 主站观察表

| 项目 | 正常/关注条件 | 常见误读 |
|---|---|---|
| 目标系统 / Adapter | 与物理连接一致 | 看见工程设备就认为已绑定当前网卡 |
| Master Actual State | 与所需从站运行阶段相容 | 把 Startup/Requested 当 Actual |
| 从站 Current / Requested | 最终均 OP | 请求已发但实际仍 SAFEOP |
| Cyclic Send Frames | 周期通信启动后持续增长 | 用 Queued 计数替代 |
| Cyclic Frames/sec | 应非零；数值与配置和帧组织相符 | 直接当 PLC 执行次数或电流环频率 |
| Queued | 反映非周期流量 | 能读 CoE 就断言 PDO 已运行 |
| 完整 InfoData.State | 正常无附加异常时为 8 | 只看低四位，忽略高位标志 |
| WcState | `0/FALSE` 表示上一周期对应通信有效 | 当成原始 WKC 数值或物理测量有效位 |
| AL Status / Code | 原始状态和原因联合看 | 将 Error List 消息编号当 AL Code |
| CRC、Lost Frames、Tx/Rx Errors | 保存基线，观察是否新增 | 清零后失去故障证据，或把旧计数当新故障 |
| CoE Online | 真正在线读取身份/映射 | 勾选 Offline Data，读取的只是描述默认值 |

`WcState=1` 时，输入可能保持上次有效值。因此画面中速度、计数“看起来正常”不保证是新数据。参见 [Beckhoff WcState](https://infosys.beckhoff.com/content/1033/b110_ethercat_optioninterface/1984417163.html)。

### 11.3 初始化结果与诊断结构

`ethercat_diagnostics` 是全局指针；确认非空后展开 `*ethercat_diagnostics`。不同 Keil 符号解析方式下也可展开指针指向的结构，不要为观察额外执行 getter。

| 字段 | 预期或解释 | 更新与有效性 |
|---|---|---|
| `ethercat_init_status` | 0 未初始化、1 READY、2 LAN9252_ERROR、3 SSC_ERROR | 初始化返回副本，不是实时 OP 状态 |
| `byte_test` | `0x87654321` | 启动 probe 留下的值，不是持续自检 |
| `id_rev` | 高 16 位 `0x9252`；历史读到 `0x92520001` | 低位芯片修订不应强行套用固定单板值 |
| `hw_cfg` | `0x08000000` Ready 位应置位 | 可存在其他位，不要求整字永远只等于该值 |
| `pdi_control` | 项目要求 `0x80` | 启动时读取的单字节 |
| `eeprom_status` | 错误掩码 `0xF800` 不应触发 | 零不是唯一正常值；历史健康快照 `0x0080` |
| `al_status` | 低四位 1/2/4/8，bit4 为错误 | 正常服务中约每 100 ms 读取；停服后可能陈旧 |
| `al_status_code` | 正常 0；非零按原始原因查 | 同上 |
| `al_event` | 当前事件位图 | 不是必须始终为零，动态事件可以正常出现 |
| `last_driver_error` | 0 表示无端口锁存错误 | 首错保持到显式初始化，不因后来一次成功清除 |
| `spi_timeout_count` | 同一轮无异常时不应新增 | 不能只看是否为零，应结合起始值和是否重启 |
| `pdi_error_count` | ESC `0x030D` 单字节计数 | 硬件快照，关注增长；不是软件终身累计 |
| `lost_link_count` | `0x0310..0x0312` 三个端口计数之和 | 包含通常不用的端口 2；硬件计数可饱和 |
| `ethercat_service_max_us` | 单次服务历史最大耗时 | 不是主站周期，不是一次 SPI 的线上时间 |
| `rx_control_word` | 最近发布的应用控制字影子 | 正常约 100 ms 观察一次，不必与 PLC 同一瞬间一致 |
| `tx_status_word` | 应用状态字影子 | 不是 ESC AL Status |
| `tx_cycle_counter` | 应用层计数影子 | 两版语义不同，见后文 |

probe 遇到首个错误即返回，后续尚未读到的字段可能为零；不能用它们断言对应环节正常。服务故障也可能发生在一次诊断更新中途，结构不一定代表同一时刻的完整硬件快照。

### 11.4 SSC 内部变量：仅在需要深入定位时加入

| 符号 | 含义 | 正常阶段判断 |
|---|---|---|
| `bInitFinished` | SSC 初始化完成 | 完成 `MainInit()` 后 TRUE |
| `nAlStatus` | SSC 内部当前 AL 状态影子 | 与实际状态对照；故障停服后不能只信本地影子 |
| `bMbxRunning` | 邮箱运行 | PREOP 及适用的更高状态为 TRUE |
| `bEcatInputUpdateRunning` | 过程输入更新运行 | SAFEOP/OP 正常为 TRUE |
| `bEcatOutputUpdateRunning` | 过程输出更新运行 | 完成 OP 转换后 TRUE |
| `bEcatFirstOutputsReceived` | 曾轮询到首个输出过程事件 | SAFEOP→OP 等待的重点；状态清理可复位 |
| `bEcatWaitForAlControlRes` | 等待状态转换完成 | pending 时可能 TRUE，不等于立即死锁 |
| `bApplEsmPending` | 应用转换回调待完成 | 结合前后状态和超时分析 |
| `EsmTimeoutCounter` | SSC 状态转换等待计时 | 有停止/未激活值，不把负数一律视为异常 |
| `nPdOutputSize` / `nPdInputSize` | 从站过程输出/输入长度 | 电机版 8/20 B；通信版 2/6 B |
| `nEscAddrOutputData` / `nEscAddrInputData` | 本地过程 RAM 地址 | 当前配置为 `0x1100/0x1400` |

内部变量能否直接显示取决于当前 AXF、优化和符号范围。静态符号发生歧义时使用正确编译单元上下文，不通过改固件去“制造”一个解释。无须在正常使用时全部展开。

### 11.5 SPI/HAL 瞬时状态与首次故障快照

`hspi1.State`、`hspi1.ErrorCode` 是瞬时/返回后 HAL 信息。运行时偶尔 BUSY 不等于卡死，错误返回后 READY 也不证明刚才没有失败。

#### `g_lan9252_first_fault`

| 字段 | 含义 |
|---|---|
| `valid` | 必须为 1 才解释其余字段 |
| `address` | 失败的物理 SPI 主机寄存器地址 |
| `esc_address` | 关联的逻辑 ESC 地址；直接 probe 为 `0xFFFFFFFF` |
| `command` | `0x0B` 快读或 `0x02` 写，不直接等于上层业务方向 |
| `phase` | 1 头部，2 数据阶段 |
| `reason` | 1 transport 前耗尽预算；2 transport 返回失败；3 transport 成功后判定超预算 |
| `status` | LAN9252 驱动错误枚举 |
| `elapsed_us` / `budget_us` | 本次物理访问耗时和预算；含一定软件处理开销 |

#### `g_lan9252_hal_fault`

| 字段 | 含义 |
|---|---|
| `valid` | 同一次首次失败有无板级 HAL 现场 |
| `reason` | 1 HAL 前耗尽预算；2 HAL_TIMEOUT；3 HAL_ERROR 且 FLAG/EOT 路径；4 HAL 后超预算；5 其他错误/BUSY |
| `hal_status` | 0 OK、1 ERROR、2 BUSY、3 TIMEOUT；`0xFFFFFFFF` 表示未调用 HAL |
| `hal_error` / `hal_state` | HAL 返回当时记录，不是所有失败瞬间的原始值 |
| `elapsed_us` | 当前 transport 回调耗时，不是整个 ESC 业务耗时 |
| `timeout_us` / `timeout_ms` | 剩余微秒预算和交给 HAL 的毫秒参数 |
| `chunk_length` | 当前 HAL 分块长度 |
| `spi_sr/cr1/cr2/cfg1/cfg2` | HAL 返回后的寄存器现场 |
| `tx_remaining/rx_remaining` | HAL 返回后剩余计数，HAL 可能已清零 |

两份首次快照不会因后续成功、BYTE_TEST 对照或显式 `EtherCAT_Init()` 自动清空，默认保持到 MCU 新一轮启动。驱动层独立预算超时可能没有 HAL 快照；不能拿下一次不相关 HAL 故障补成同一次证据。

### 11.6 BYTE_TEST 三种只读对照

只在需要定位 SPI 帧问题、且操作者明确安排诊断构建时参考，不要求每次 OP 都重复：

| 子结构 | 帧 | 正确数据位置 |
|---|---|---|
| `fast_split` | `0B 00 64 00`，保持 CS 低，分两次 HAL 完成头和数据 | `rx[4..7]` |
| `fast_single` | 同样 8 B，一次 HAL | `rx[4..7]` |
| `normal_single` | `03 00 64` 加 4 B 数据时钟，共 7 B | `rx[3..6]` |

正确数据字节为 `21 43 65 87`，组合值 `0x87654321`。`done=1` 后看结果，三个检查全部通过时 `passed_mask=7`。

`value_valid=1` 只表示 HAL 调用成功并组合了数值，仍须比较期望值。该对照不会替代原初始化状态，也不自动解锁故障；当前电机分支不应因符号存在就被误认为每次都执行这组三读。

### 11.7 当前电机版的 PLC 观察项

| 变量 | 待机检查或解释 |
|---|---|
| `State` / `WcState` | 正常 8 / FALSE |
| `bHealthy` | 由上述两项计算，不包含全部应用故障检查 |
| `CommandSequence` | 每个 PLC 周期递增，允许正常回绕 |
| `AcceptedSequence` | MCU 已接受的前进序号，持续跟随即可，不要求每个画面瞬间差固定值 |
| `ControlWord` / `TargetSpeed` | OpenAngle 正常待机为 `0x0100 / 0` |
| `bOpenAngleProfile` | `StatusWord & 0x0100` 非零 |
| `bElectricalOutputOff` | `StatusWord & 0x0400` 非零；是软件发布的电气关闭条件 |
| `bControlFeedbackValid` | `StatusWord & 0x0200` 非零；待机时 FALSE 正常 |
| `bSpeedMeasurementValid` | 当前固定 FALSE，不能依据 ActualSpeed 判停稳 |
| `nPhase` / `bLocalFault` | 待机通常 0 / FALSE；90 / TRUE 为 PLC 锁存故障 |
| `MotorFault` / `BridgeFault` | 应结合来源分别判断，不是 AL Status Code |

正常健康的 OpenAngle Ready 常见 `StatusWord=0x0519`，即十进制 1305；但应按位解释，不把整字恒等某个常数作为唯一协议检查。1305 也不是 EtherCAT 状态编号。

## 十二、寄存器、PDO、工作计数和时间参数速查

### 12.1 网络 ESC 视图与 SPI 主机视图不是同一套地址

| 地址空间 | 地址 | 用途 |
|---|---:|---|
| SPI 主机寄存器 | `0x0050` | ID_REV |
| SPI 主机寄存器 | `0x0064` | BYTE_TEST |
| SPI 主机寄存器 | `0x0074` | HW_CFG |
| SPI 主机寄存器 | `0x0300/0x0304` | CSR DATA / CMD 窗口 |
| SPI 主机寄存器 | `0x0308..0x0314` | PRAM 地址/长度和命令窗口 |
| ESC 逻辑寄存器 | `0x0120` | AL Control，主站请求及错误确认 |
| ESC 逻辑寄存器 | `0x0130` | AL Status，实际状态 |
| ESC 逻辑寄存器 | `0x0134` | AL Status Code，错误原因 |
| ESC 逻辑寄存器 | `0x0140` | PDI Control 低字节 |
| ESC 逻辑寄存器 | `0x0220` | AL Event |
| ESC 逻辑寄存器 | `0x030D` | PDI 错误计数 |
| ESC 逻辑寄存器 | `0x0310..0x0312` | lost-link 端口计数 |
| ESC 逻辑寄存器 | `0x0502` | EEPROM Control/Status |
| ESC 逻辑寄存器 | `0x0800+8×n` | SMn 配置/状态区起点 |
| ESC 过程 RAM | `0x1000..0x1FFF` | 本工程邮箱和 PDO 所在范围 |

例如 SPI 的 `0x0304` 是 CSR 命令窗口，并不是 TwinCAT Memory 页面里同号地址的业务含义。记录故障时同时保存 `address` 与 `esc_address`，不能混写。

若 Memory 在 `0x0140` 显示两字节字值 `0x0E80`，目标 PDI 仍是低字节 `0x80`；高字节属于相邻配置。寄存器地址及 PDI 配置原理参考 [Microchip LAN9252 DS00001909A](https://ww1.microchip.com/downloads/en/DeviceDoc/00001909A.pdf)，具体常量以本仓库 `lan9252_regs.h` 为准。

### 12.2 AL Status 和 InfoData.State 的区别

- 原始 AL Status 低四位：INIT=1、PREOP=2、BOOT=3、SAFEOP=4、OP=8；bit4 为错误。
- BOOT 只是状态编码，本固件没有实现可用的 FoE/Bootstrap 更新路径。
- TwinCAT 的 InfoData.State 还可组合身份、初始化、缺失连接等高位信息；它不是只有低四位的原始 AL 寄存器。
- 例：`0x0014` 应按 SAFEOP＋AL 错误理解，而不是十进制 20 的“新状态”。`0x0042` 含 PREOP 和主站初始化异常标志，不应忽略高位。
- Error List 中 `(1001)`、时间戳、软件消息号和原始 AL Code 属于不同字段。

完整状态位定义可核对 [TwinCAT Online / InfoData.State](https://infosys.beckhoff.com/content/1033/tc3_io_intro/1446518411.html)。

### 12.3 当前电机版 PDO 字节表

| 方向 | 偏移 B | 字段 | 类型 | 含义 |
|---|---:|---|---|---|
| Rx | 0 | ControlWord | UINT16 | 配置确认、Enable、FaultReset |
| Rx | 2 | TargetSpeed | INT16 | 0.1 等效 rpm，负值必须保持有符号 |
| Rx | 4 | CommandSequence | UINT32 | PLC 前进序号 |
| Tx | 0 | StatusWord | UINT16 | 应用位图，不是 AL 状态 |
| Tx | 2 | CycleCounter | UINT32 | 运行条件满足时的应用轮询计数 |
| Tx | 6 | ActualSpeed | INT16 | 当前 OpenAngle 为无效零占位 |
| Tx | 8 | ActualIq | INT16 | 虚拟坐标系 q 轴电流，mA |
| Tx | 10 | MotorFault | UINT16 | 电机故障 |
| Tx | 12 | BridgeFault | UINT16 | 命令/桥接/实验策略故障 |
| Tx | 14 | ActiveTargetSpeed | INT16 | 活动磁场频率换算的等效 0.1 rpm |
| Tx | 16 | AcceptedSequence | UINT32 | MCU 最近接受的命令序号 |

线上按小端打包，不使用带填充的 C 结构体整体 memcpy。`State`、`WcState` 是主站诊断映射，不占从站 20 B 的应用 TxPDO。

### 12.4 WKC、WcState、序号与应用计数

| 名称 | 负责证明什么 | 不代表什么 |
|---|---|---|
| 原始 WKC | 该 EtherCAT 数据报按配置被正确处理的计数 | 固定永远等于 1 |
| `WcState` | 主站比较实际与期望工作计数后的有效性 | MCU 算法新鲜、转子测量正确 |
| `CommandSequence` | PLC 应用周期在产生新命令 | 从站必然已接收 |
| `AcceptedSequence` | 从站命令层已接受前进序号 | 动作完成、转子已跟随 |
| `CycleCounter` | 本项目相应应用迭代活动 | EtherCAT 主站精确周期或电机圈数 |

WKC 的期望值由数据报命令、映射和参与从站决定；不能把一次 Memory 读 WKC=1 套用于所有周期 LRW 命令。参见 [Beckhoff Working Counter / 命令说明](https://infosys.beckhoff.com/content/1033/tc3_io_intro/1446515467.html)。

通信版在有效 OP 交换后计数增长；电机版只有 `EMC_RUNNING` 等条件满足时才增长。所以不启动电机而验证 OP 时，应看序号跟随和通信标志，不应为了让计数器增长而启动电机。

### 12.5 不同时间参数属于不同层

| 参数 | 当前代码/含义 | 不能混同 |
|---|---|---|
| Direct 访问预算 | 1000 μs | 不是 AL 状态转换 timeout |
| CSR / PRAM 业务预算 | 各 10000 μs | 不是主站周期 10 ms 的承诺 |
| HW Ready 等待 | 100000 μs | 不是命令心跳 |
| HAL 毫秒超时 | `ceil(剩余μs/1000)+1` | 不能解释成严格 1 ms 内一定返回 |
| SM 确认等待 | 1000 μs 和最多 64 次读取约束 | 完整耗时还包括端口事务和中断开销 |
| SSC PREOPTIMEOUT | 默认 `0x7D0`，2000 ms | 不等于历史主站报出的 3000 ms |
| SSC SAFEOP2OPTIMEOUT | 默认 `0x2328`，9000 ms | 不保证主站会等同样长时间 |
| 主站状态转换 timeout | 以实际 TwinCAT 配置为准 | 不是固件 SPI 预算 |
| 诊断刷新 | 约 100 ms | 不是 PDO、PLC 或电流环周期 |
| 当前交付 PLC Task | 10 ms | UI 刷新周期不等于任务周期 |
| 电机命令心跳 | 100 ms 内须有有效前进序号 | OP 可以正常但心跳仍失效 |
| 电机 TIM8/ADC | 约 100 μs / 10 kHz | 与主站 DC 未建立锁相关系 |
| OpenAngle 会话/运动上限 | 当前 10 s / 6 s | 与 OP 状态转换无关 |

本地配置中的 `MIN_PD_CYCLE_TIME=100 μs` 等声明不能作为实板达到该性能的证据。历史曾记录服务最大耗时 4510 μs；它也不是每轮固定耗时，但足以说明不能凭一次 OP 就宣称已验收 1 ms 实时性。

## 十三、故障定位：先定位层次，再讨论处理

### 13.1 快速决策树

```text
扫描不到从站？
 └─ 查目标机、网卡/驱动、端口、网线、供电、LAN9252复位/时钟
扫描到但身份异常/全FF？
 └─ 查ESI是否匹配、SII是否装载；先保存现状，不盲写EEPROM
初始化 probe 失败？
 └─ 按 BYTE_TEST / Ready / ID / PDI / EEPROM 的首失败项分流
INIT→PREOP 超时，或 PREOP→INIT 也失败？
 └─ 查 MCU 是否运行、SPI sticky fault、SSC 是否停服、邮箱配置
PREOP 健康，但主站/从站进不了 SAFEOP？
 ├─ Cyclic=0：查主站周期源、Sync Task、Config FreeRun
 └─ Cyclic已运行：查 SM/FMMU、PDO长度、同步配置及 AL Code
SAFEOP→OP 等待？
 └─ 查有效输出是否实际到达、bEcatFirstOutputsReceived、主站状态
OP 正常但应用不能启动？
 └─ 查 PLC nPhase、profile、命令序号、功率锁和电机故障，停止围绕 EEPROM 排查
```

### 13.2 常见现象与优先证据

| 现象 | 首先保存/检查 | 不应立即采取的动作 |
|---|---|---|
| 找不到设备 | 网卡绑定、Link、目标机和从站端口 | 先修改 MCU PI 或 PDO |
| `PFFFFFFFF RFFFFFFFF`、EEPROM 连续 FF | 原始 EEPROM、PDI、供电和装载状态 | 套用别家设备 XML 或反复盲写 |
| `BYTE_TEST` 错值但 HAL_OK | 原始 RX、三种帧对照、CS 连续性和 IO 保持 | 仅凭 HAL_OK 宣称 SPI 正常 |
| 初始化成功后过一会儿不能转换 | 首错、端口锁存、服务诊断是否停止刷新 | 用旧 init=READY 否认后来访问失败 |
| INIT→PREOP timeout | 是否停在 main、邮箱、持续服务、首失败地址 | 单纯增大主站 timeout |
| `Master state PREOP is insufficient` | 父 Device 状态、Sync Task、Cyclic | 只反复请求 Box OP |
| Queued 增加、Cyclic=0 | FreeRun / PLC周期源是否真正开始 | 认为网络已通所以必是从站错误 |
| SAFEOP 稳定、OP 不确认 | 首次有效输出、正确长度和 watchdog | 强改本地 nAlStatus 或禁用 watchdog |
| 已 OP 但 WcState=TRUE | 对应 SyncUnit、期望WKC、丢帧、状态和链接 | 使用冻结输入继续作运动判断 |
| State 恢复 8，nPhase 仍 90 | PLC锁存、BridgeFault、启动释放及复位边沿 | 重写 EEPROM 或强制 nPhase=0 |
| F5 后短暂 OP→INIT，再恢复 | 本轮是否复位/暂停、时间戳 | 未区分人为中断就宣告硬件异常 |
| `CycleCounter=0` | 当前版本和应用是否运行 | 在电机版待机时判定 OP 失败 |
| Frame missed 历史告警 | 新增速率、WcState、AL状态、是否调试中断 | 擦除记录或一律判作/排除真实故障 |

### 13.3 AL Status Code 分类

以下按本地 `ecatslv.h` 和实际检查代码解释。不是每种外部现象都必定出现某一个码；SPI 失败时 MCU 可能来不及更新 AL Code，主站看到的也可能是旧值。

| AL Code | 含义 | 本项目优先排查 |
|---:|---|---|
| `0x0000` | 无 AL 错误 | 仍需检查主站状态和应用层故障 |
| `0x0011/0x0012` | 非法状态转换/未知请求 | 请求路径和状态值，不手动写非法状态 |
| `0x0013` | 不支持 Bootstrap | 本应用不支持 FoE 更新路径 |
| `0x0016` | PREOP 邮箱配置无效 | SM0/1 地址、长度、控制和重叠 |
| `0x0017` | SM 配置无效 | revision、地址、长度、方向 |
| `0x001B` | SM watchdog | 周期输出是否持续，MCU服务是否正常 |
| `0x001D` | 输出配置无效 | 当前电机版 SM2 是否 8 B |
| `0x001E` | 输入配置无效 | 当前电机版 SM3 是否 20 B |
| `0x0024/0x0025` | 输入/输出映射无效 | 映射位宽、次序、assignment |
| `0x0027` | 不支持 FreeRun | 与当前目标相矛盾，查错误固件/描述/能力声明 |
| `0x0028` | 不支持所选同步方式 | 当前无 AL Event 时拒绝用户指定非 FreeRun |
| `0x0029` | FreeRun 需要三缓冲模式 | 核对过程 SM 的缓冲配置 |
| `0x0030` | DC 同步配置无效 | 当前 DC 关闭，不应配置为主动 DC/Sync |
| `0x0051` | EEPROM 错误 | 装载、校验、版本以及写入后是否真正重启 |

AL Code、`LAN9252Status`、HAL Status、`MotorFault` 和 `BridgeFault` 是五种命名空间。比如数字 7，在驱动枚举中是 PDI 错误，在电机故障枚举中是过流；不能只记录“报错 7”。

### 13.4 LAN9252 驱动错误枚举

| 值 | 枚举 | 优先方向 |
|---:|---|---|
| 0 | `LAN9252_OK` | 无端口锁存错误 |
| 1 | `LAN9252_ERR_ARGUMENT` | 地址、长度或缓冲区接口使用 |
| 2 | `LAN9252_ERR_IO` | HAL错误/BUSY等，结合首次现场 |
| 3 | `LAN9252_ERR_DIRECT_TIMEOUT` | 物理事务/HAL预算路径 |
| 4 | `LAN9252_ERR_BYTE_TEST` | SPI帧、返回值与接口准备 |
| 5 | `LAN9252_ERR_READY_TIMEOUT` | LAN9252未在等待期内Ready |
| 6 | `LAN9252_ERR_CHIP_ID` | 芯片识别值不符 |
| 7 | `LAN9252_ERR_PDI` | 项目要求的SPI PDI不是0x80 |
| 8 | `LAN9252_ERR_CSR_TIMEOUT` | ESC CSR业务未完成 |
| 9 | `LAN9252_ERR_PRAM_TIMEOUT` | 过程RAM/FIFO业务未完成 |
| 10 | `LAN9252_ERR_EEPROM` | EEPROM装载/校验等错误位 |
| 11 | `LAN9252_ERR_SM_TIMEOUT` | SM确认等待超时；核对记录的channel |

`syncman_timeout_channel` 保存在端口观察结构中，不是 `EtherCATDiagnostics` 的直接字段。无需要时不必增加额外 Watch，更不要为读取它在 Watch 中执行硬件访问函数。

<a id="history"></a>
## 十四、历史定位过程：为什么这些注意事项需要保留

### 14.1 EEPROM 空白与 PDI 不符

历史从未知身份、EEPROM 连续 FF 开始。网口读取 PDI/EEPROM 信息提供了独立于 MCU SPI 的证据；写入匹配配置并重新上电后，名称和 PDI 恢复正常。

结论：配置装载本身会影响接口工作。不能把两个同批空白板都不能工作归因于两颗芯片均损坏；也不能把历史成功处理变成每次 OP 失败都重写 EEPROM 的理由。

### 14.2 分段 SPI 帧的 IO 保持

历史出现 `BYTE_TEST=0x0ECB8642`，只读对照 `passed_mask=0x06`：整帧成功，分段快读失败。后来将 H7 SPI1 的 `MasterKeepIOState` 保持配置修正后，记录出现 `passed_mask=0x07` 和正确探测值。

结论：当前生产驱动在 CS 保持期间分两次 HAL 调用传头和数据，不能只用一条整帧测试证明生产路径已经无问题。不要重新把当前已核对的 IO 保持配置随意改回。

### 14.3 HAL Tick 边界的提前超时

历史首次现场：物理 `CSR_CMD=0x0304`、逻辑 `ESC=0x0004`、快读数据阶段，HAL_TIMEOUT。整次约 39 μs、transport 约 11 μs，剩余预算 977 μs，却向 HAL 传了 1 ms。

本地 HAL 按整数毫秒 Tick 差判断，靠近 Tick 边界时 1 ms 参数可能很快到期。板级改为 `ceil(剩余μs/1000)+1`，同时保留驱动前后的微秒预算判断；晚完成仍失败，不靠重试掩盖。

结论：这是不同计时粒度之间的换算修正，不是把所有 SPI 超时放宽，也不保证故障调用严格 1 ms 返回。HAL 返回时清理计数为零，不足以证明传输成功。

### 14.4 主站 Cyclic 没有运行

历史 PREOP 和在线 CoE 已正常，但 Device 主站仍不能推进；关键是 Cyclic 发送和帧率为 0，而 Queued 有流量。启动 Config Mode FreeRun 后，随后完成 SAFEOP 和 OP。

结论：主站周期源也是系统的一部分，不能将 PREOP 后所有问题继续归到 SPI。这个阶段不需要再改 MCU PI、重配 EEPROM 或关闭安全保护。

### 14.5 Debug 顺序与 PLC 故障锁存

电机联调阶段曾发生 MCU 调试复位/暂停后状态下降、重新进入 OP 后 `nPhase=90`。用户后来采用先 Debug/F5 连续运行，再操作 TwinCAT 的顺序。

结论：恢复通信和解除应用锁存需要分两步。只恢复 OP 不清除 PLC 的故障历史和启动边沿要求，复位时还要确认停止和零需求。

<a id="recovery"></a>
## 十五、异常后如何恢复：保留证据，区分恢复层次

### 15.1 故障出现后先做什么

1. 若有运动、异响、异常电流或发热，先使用可靠停机/断电手段；安全优先于取证。
2. 若安全条件允许，保存 TwinCAT 原始错误、主从站 Actual/Requested、AL Status/Code、State/WcState、Cyclic/Queued 和计数基线。
3. 记录这次是否操作过 Debug、Reset、Download、Config/Run、FreeRun开关或拔插网线。
4. 保存 init状态、诊断结构和两个首故障快照；不要在断电后试图恢复已经丢失的RAM历史。
5. 不先清CRC、重置计数、重复Start、重写EEPROM或手改valid字段。

### 15.2 一般链路/主站条件恢复

若 MCU SPI 无锁存故障，先恢复网线、周期任务和正确状态目标。按原因确认错误后重新逐级请求，观察新的错误是否出现。主站的“通信错误后重新初始化”功能可以导致暂时回 INIT；它不应与应用自己的状态控制互相竞争，也不应自动恢复电机运动。

### 15.3 SPI/端口锁存故障恢复

主站 Clear Error 只涉及相应主站/ESM层处理，不能替 MCU 清 `HW_AccessFault()`。修复实际原因、保存现场后，应在明确的新一轮中通过安全的初始化/复位流程重新启动；本工程没有承诺自动恢复。

显式 `EtherCAT_Init()` 会清服务和端口本轮状态，但不会清两份首次硬件访问快照。若要比较相互独立的冷启动，记录 MCU 真正重启的轮次，不能将旧快照当成新错误。

### 15.4 OP 恢复，但 nPhase=90

只在电机已停稳、软件输出关闭且通信健康后：

1. 释放 `bStart=FALSE`，保持零需求及心跳正常。
2. 核对 `bHealthy=TRUE`、正确的 OpenAngle profile、当前故障来源。
3. 写 `bReset=TRUE` 形成上升沿，然后释放为 FALSE。
4. 等待阶段 80 确认 MCU 故障清除、输出关闭，返回阶段 0；重新满足启动释放/Ready条件。
5. 本文只检查OP，不继续发送Start。

`BridgeFault=2` 为 SPI 故障锁存，不能指望 PDO Reset 清除；`BridgeFault=9` 为功率锁定；12为时限、13为运行中反向、14为停止超时。这些都不应直接套用 AL 状态错误处理。

### 15.5 不采取的“快速修复”

- 不强制 `nPhase`、Ready、AL Status、校准有效位或 PWM/使能寄存器绕过流程。
- 不关闭 SM watchdog、命令心跳或缩小反馈检查来换取“看起来能 OP”。
- 不同时修改 SPI 分频、超时、ESI、PDO、PLC周期和供电，避免失去定位依据。
- 不把电源没有进入1A限流当作相电流安全证明。
- 不因一次OP成功宣称连续10分钟、1ms、DC、正反转、噪声或保护延迟验收完成。
- 不为记录文档制造新的带电实验；故障注入、断线、周期缩短等需单独安排。

1. **能扫描，不等于 MCU / SSC 已经正常运行。**
2. **能读在线 CoE，不等于主站周期输出已经开始。**
3. **主站请求 OP，不等于从站实际已经确认 OP。**
4. **从站实际 OP，不等于电机已经允许启动或测量有效。**
5. **恢复 OP，不等于清除了 PLC 和 MCU 的应用故障锁存。**
6. **调试时先保留现场、区分层次，再做单项改变；不要靠放宽保护或反复重写配置换取表面成功。**
