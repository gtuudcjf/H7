日期：2026-09-27。隔离分支：`feature/vofa-dual-telemetry`；原始工程 main 未自动合并。

## 测试证据

- 编码测试先因接口不存在失败，随后通过；验证八通道、小端浮点、帧尾及非有限值清零。
- 调度测试先因接口不存在失败，随后通过；验证独立缓冲区、忙跳帧、开关、完成/错误、节拍回绕与长延迟不补发。
- 外设接线检查先因未接入失败，随后通过。
- 可执行 H7 适配测试覆盖字段顺序、PRIMASK 保持、USB 离线、发送映射、独立开关和 UART RX 错误不破坏 TX。USB 提交前 DeInit 竞态测试先失败，保护区内重新声明 busy 后通过。
- 独立审查检查五项 Review Focus，未发现 Critical 问题；发现 USART1 生成区所有权问题。回归检查先因 handler 位于 USER1 保留区失败，改为标准 CubeMX handler 布局后通过。
- 修正后的 `tests/run_motor_telemetry_suite.ps1`：8/8 检查通过（核心与适配行为测试、接线检查、六项既有配置/集成回归）。
- 修正后 Keil 全量重建：0 Error(s)、0 Warning(s)，耗时 55 秒；Code=65440、RO-data=844、RW-data=488、ZI-data=11032 字节。源码差异检查通过。构建日志位于隔离工作树 `MDK-ARM/vofa-build.log`；生成的固件与构建产物不纳入源代码提交。
- `motor_control.c` 与 `motor_params.h` 相对基线没有差异。

## 执行中作出的取舍

1. 补充计划文件列表遗漏的 `stm32h7xx_it.h` USART1 IRQ 声明，使声明完整；若判断错误，代价是一个未使用声明。
2. UART RX-only HAL 错误不释放活跃 TX 缓冲区，因为 H7 HAL 此时不终止中断发送；若 HAL 的终止方式变化且未识别，端口可能保持 busy，需要复位恢复。
3. USB 提交仅屏蔽 OTG FS IRQ，并在保护区重建 busy 占用，避免 DeInit/重连竞争，不屏蔽电机中断；代价是 USB IRQ 被短暂延迟。
4. 在计划的源码接线检查之外增加可执行 HAL/CDC 替身测试，验证实际适配层逻辑；代价是测试不能证明物理 USB、实际 ISR 时序或硬件实时性。

## 待更正的次要项

`h7-vofa-telemetry.md` 的电流环纹波说明写了 20 kHz，实际控制周期为 100 μs，即 10 kHz；此处仅为文档笔误，没有更改控制频率。100 Hz 遥测仍只适于慢速趋势，不能验证电流环高频纹波。

## 实机验收边界

没有在此环境连接用户电机或两个 COM 口。本记录不证明 Windows CDC 枚举、物理拔插、主机慢读及实际电机误差已验收；须按使用文档分别验证 UART、CDC 和两端口同时运行，并对照原有实时故障/超时计数。
